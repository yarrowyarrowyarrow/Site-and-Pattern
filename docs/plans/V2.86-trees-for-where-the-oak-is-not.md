# V2.86 — trees for where the oak is not

*The author asked, after V2.85 stopped offering Bur Oak to Alberta yards: which
native trees of this region can do what the oak does? The answer was a group of
genera rather than one tree, and asking it turned up four things wrong in the
app. This increment fixes three of them and stages seven trees the catalogue
lacked. The seven cannot ship yet, for a reason the author set.*

## The question, answered first

Bur Oak **is** native to the region the app covers: to southeastern
Saskatchewan, where V2.85 still offers it on any lot of about 900 m² or more.
It is not native to Alberta. What it does as a hub (Tallamy ranks *Quercus*
first for caterpillars) depends partly on insects that live only on oaks. Of
the 26 GloBI records for Bur Oak cached in `data/fetched/`, 21 are oak gall
wasps and mites. Alberta has no native oak, so most of that fauna is not here.
Alberta's caterpillars use the next four genera in Tallamy & Shropshire's
ranking: willow, cherry, birch and poplar. All four were already in the
catalogue.

## What was wrong, found by answering it

1. **The keystone tag skipped birch and oak.** The tag has always been a genus
   claim (`ecological_role` calls it "Tallamy's high-value genera"). Measured
   over the catalogue: every member of seven genera carried it and nothing
   outside them did. Two of Tallamy & Shropshire's top five woody genera were
   missing, so a design with Paper Birch earned no keystone credit and one with
   any willow did. Keystones are 15 of the Habitat Value Score's 100 points.
2. **The yard-size rule ignored height.** V2.85's rule reads the crown, and
   narrow crowns let a 25 m Lodgepole Pine and a 15 m Jack Pine into a 216 m²
   front yard. In V2.85's own test runs they were **the trees in three of the
   nine yards** (Edmonton pet + kid: both; Calgary: Lodgepole; Regina and
   Edmonton with no goal: Jack Pine). A 25 m pine reserved most of the Calgary
   yard's anchors.
3. **"Burr Oak" found nothing**, in the desktop search or on the website. It
   is a common spelling; the catalogue follows VASCAN's "Bur".
4. **Bur Oak's documented edges barely exist**: 2 caterpillar hosts, against 17
   for Chokecherry. That is documentation, not ecology. The edge sources were
   Alberta-centric and the oak is a Saskatchewan tree. **Not fixed here**: it
   needs Saskatchewan and Manitoba oak records sourced over the network (F165).

### Why the trees wait

Since V2.80 the author's rule has been that nativity is read from a flora or
the species does not ship ("only facts backed by data"), and
`tests/test_nativity.py` fails on any unsourced row. VASCAN, GBIF,
iNaturalist and the publishers were all refused by this session's network
policy (measured: `data.canadensys.net`, `api.gbif.org`, `nature.com`,
`nwf.org`, `ncbi.nlm.nih.gov` all return 403 at the proxy). So each tree was
written as a whole catalogue row and held out of the catalogue:

- `validate_pending_species` holds the rows to the catalogue's own rules now,
  plus four of its own. A pending row carries no source. It is not already a
  catalogue row. It does not reverse an `excluded_taxa.json` call. It does not
  take another row's common name.
- `fetch_flora_nativity.py` asks VASCAN about the pending names alongside the
  catalogue's, so one archive run answers both.
- `ingest_flora_nativity.py` reports two new buckets. **promote** is a plain
  yes: an accepted name, recorded native in AB and/or SK. **hold** is anything
  else. `--apply` moves each promoted row into `plants_master.json` with
  **VASCAN's** province list, not the one written on the row, and with the
  source stamped. Running it twice promotes once.

| Tree | Written as | Why it is here |
|---|---|---|
| Peach-leaved Willow, *Salix amygdaloides* | AB, SK | The prairie's tree-sized willow; keystone genus |
| Plains Cottonwood, *Populus deltoides* | AB, SK | The prairie river-valley tree closest to Bur Oak in size |
| Narrowleaf Cottonwood, *Populus angustifolia* | AB | Southwestern Alberta's cottonwood |
| Manitoba Maple (Box Elder), *Acer negundo* | AB, SK | Native in southeastern Alberta and Saskatchewan; hosts the giant silk moths (the catalogue's own moth notes). Self-seeds; seeds toxic to horses; both in its notes |
| Round-leaved Hawthorn, *Crataegus chrysocarpa* | AB, SK | A yard-sized thorny tree for birds; `has_thorns` set, so the kid-safe filter excludes it |
| Rocky Mountain Juniper, *Juniperus scopulorum* | AB | The dry-slope evergreen; alternate host of the saskatoon rust, said in its notes |
| American Elm, *Ulmus americana* | SK | Native in southeastern Saskatchewan; Dutch elm disease in its notes |

What the rows assert beyond nativity follows the catalogue's own convention
for estimates. Sizes, zones, pH and prices are editorial, `sourcing_notes`
says "Estimate ... not checked against a nursery listing", and the one flower
colour carries `flower_colour_source: estimated`. No medicinal or traditional
use is written on any of them (P12). `host_plant` is claimed only where the
catalogue's own Lepidoptera notes name the genus as a larval host (*Salix*,
*Populus*, *Acer*, *Ulmus*).

**Green Ash was considered and not staged.** It is native to southern
Saskatchewan and possibly southeastern Alberta, and emerald ash borer has been
in Winnipeg since 2017. A catalogue that recommends plantings should not start
recommending ash now. That is the author's call to reverse, and it is not
recorded in `excluded_taxa.json`, because that file is for calls with an
authority behind them.

### The lineage change, and the trap it closes

The first simulation of a promotion (on a scratch copy, stamping each row as
VASCAN would) found that **a promoted tree would never be offered anywhere**.
`search_plants` reads the occurrence-derived rows for a species when it has
them and the column when it does not. The generator passed the site's
ecoregion literally, and a new tree has no derived rows and a column that says
`riparian` or `zone_prairies`. The plant panel has expanded along the lineage
since V2.68. The generator never did.

Now it does. Measured on the V2.85 comparison set, **it changes no existing
design**: every species already in the catalogue but eight has derived rows,
which supersede the column. After a simulated promotion, the site filter
offers:

| Pin (ecoregion) | Promoted trees offered |
|---|---|
| Edmonton (Aspen Parkland) | Manitoba Maple, Peach-leaved Willow, Round-leaved Hawthorn |
| Calgary, Pincher Creek (Fescue Grassland) | the same three, and Narrowleaf Cottonwood |
| Lethbridge, Medicine Hat (the mixed grasslands) | the same three, and Plains Cottonwood |
| Crowsnest Pass (Northern Continental Divide) | Narrowleaf Cottonwood, Rocky Mountain Juniper |
| Regina, Saskatoon | the Lethbridge four, and American Elm |

The rows carry coarse tags (an ecozone, or the ecoregions a tree is certain
of) that the GBIF run replaces. The two cottonwoods' tags were narrowed after
the first simulation offered both in Edmonton. Before the GBIF run a promoted
tree ranks *unrecorded*, level with *elsewhere* and behind every species
recorded near the yard. So on the acreage runs it was offered and not picked,
which is the V2.85 ranking working as intended.

## Decided, and worth the author knowing

- **The keystone list names genera, not species**, as the tag always did in
  practice. Dwarf Birch, a bog shrub, is keystone now because every *Betula*
  is, the same way every shrub willow already was.
- **The height rule is a judgement**, like V2.85's 25% footprint share: a tree
  taller than the lot is wide shades every neighbour and, when it falls,
  lands on one.
- **A pending row's own province list is not what ships.** It records what the
  person writing the row expected. The ingest writes VASCAN's.

## Deliberately not done

- **Bur Oak's Saskatchewan fauna (F165).** 21 of its 26 cached candidates are
  gall wasps and mites the registry does not carry, and two are records the
  candidate filter rightly refused: *Polistes fuscatus* and *Harmonia axyridis*
  as larval hosts of oak. Sourcing it properly is a GloBI and literature job on
  a machine with egress.
- **Black Hawthorn has thorns and no `has_thorns`.** Found while copying its
  conventions for the new hawthorn. It is a one-field fix to a safety filter
  and deserves its own line in a data increment rather than a ride here.
- **Larval-host records by genus.** The Lepidoptera attribute file names host
  genera (*Salix* for ten species, *Populus* for nine) that
  `src/db/derived_edges.py` does not expand, as it does for nectar and pollen.
  That would give the staged trees edges on arrival. It changes the edge layer,
  so it is its own increment.

## Handing over: what the author runs

In this order, on a machine with internet. Every step prints what it did.

1. `python scripts/fetch_flora_nativity.py --from-archive <path to the VASCAN
   Darwin Core Archive .zip>` asks VASCAN about the catalogue and the seven
   pending names, with no network if the archive is local. Run it with no path
   to print where to download the archive. It rewrites
   `data/fetched/flora_nativity.json`.
2. `python scripts/ingest_flora_nativity.py` **reports only**. Read the
   `promote` and `hold` buckets. Every other bucket should be empty, because
   V2.80 applied them. If one is not, VASCAN has changed and that is its own
   decision.
3. `python scripts/ingest_flora_nativity.py --apply` promotes. It also applies
   any narrowings the report showed, which is why step 2 comes first.
4. For range maps and "recorded near the yard" ranking:
   `python scripts/seed_ecoregion_ranges.py --resume --species "<name>"` for
   each promoted tree (network). **`--resume` is load-bearing.** Without it a
   `--species` run writes only those species and replaces every other row in
   `plant_ecoregions.json`. Then `python scripts/seed_species_ranges.py` and
   `python scripts/seed_occurrence_points.py` **with no `--species`**. Both
   read the local cache in seconds, and both also replace their whole output
   file when given `--species`.
5. Bump `_SCHEMA_VERSION`, or no existing install sees any of it.

## What could not be verified here

- **VASCAN's answer for any of the seven.** Their provinces come from regional
  sources read through a search engine (AWES, Tree Canada, the USFS FEIS
  entries, Saskatchewan Wildflowers, ABMI, one VASCAN page's search snippet),
  which is exactly why they are pending rather than shipped.
- **The Tallamy & Shropshire figures** behind the keystone list were not read
  from the paper; the paper and the NWF keystone lists were blocked. The top
  five woody genera are the widely reproduced part of that work and the part
  used here.
- **The GUI.** The generator, search and gate were exercised headlessly and
  by the suite.
