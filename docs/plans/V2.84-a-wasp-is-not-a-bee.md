# V2.84 — a wasp is not a bee

*The first increment from the V2.83 review's backlog group M: the wasps filed as
bees (F153), the website on a phone and in a search result (F156), and the four
tests that had stopped testing anything when the data moved underneath them.*

## F153 — 43 wasps were counted as bees

The first screen of `/wildlife/` read **"American Sand Wasp · *Bembix
americana* · native bee"**, and *Ammophila aberti*, a thread-waisted wasp, below
it.

**The cause is one line.** `scripts/fetch_fauna_edges.py` maps GloBI taxon paths
to the app's five `taxon` values, first hit wins, and it listed
`("Apoidea", "bee")`. Apoidea is the superfamily, and it holds the apoid wasps
as well as the bees; the bees are the Anthophila clade inside it, which the same
table already named, family by family, on the lines after.

**Measured before changing anything:**

| | |
|---|---|
| Genera filed as `bee` | 60 |
| of which bee genera (Apidae, Andrenidae, Halictidae, Colletidae, Megachilidae, Melittidae) | 39 |
| of which apoid wasps (Sphecidae, Philanthidae, Bembicidae, Crabronidae, Pemphredonidae) | **21 genera, 43 animals** |
| Relationship edges on those 43 | 174 (138 nectar, 34 pollination records, 2 larval host) |
| Plants reporting fewer bees afterwards | 51 (Boreal Yarrow 151 → 129, Canada Goldenrod 56 → 43); **none drops to zero** |
| Habitat Value Score headline | unmoved: its components do not count bees |

**Whoever wrote the rows knew.** Every one of the 43 descriptions already said
what it was: *"Beewolves, sand-country natives."*, *"Crabronid wasps, native
wood-nesters."*, *"Mud daubers. S. caementarium is native to North America…"*.
Only the `taxon` field was wrong, which is the field the site's label, the app's
bee counts and the 3D scene's choice of body all read.

**What changed.** The 43 rows move to `other_insect` with the 🪲 icon, which is
where every other wasp in the catalogue already was (yellowjackets, paper wasps,
potter wasps, spider wasps). None carried bee morphology or a photograph, so no
other table moves. `("Apoidea", "bee")` is gone from the fetch mapping, so an
apoid wasp now falls through to the Insecta catch-all like every other wasp.
`data_quality.validate_bee_taxon` joins the gate:

- **error** for a `bee` row in a known apoid-wasp genus (`APOID_WASP_GENERA`),
  because that is the mistake that shipped and it has one right answer;
- **warning** for a `bee` row in a genus neither table lists
  (`BEE_GENERA`), because that is how the next non-bee would arrive, a hover
  fly say, and it should be looked at once rather than trusted.

Proven both ways: 0 errors on the corrected data, 43 on V2.83's. Schema
**v86**, so installed copies reseed; the v85 bump in V2.82 had shipped without a
line in the version history and has one now.

**Found on the way and left alone, on purpose:**

- ***Vespula germanica* is filed `ab_native = 1` with the note "Ground
  yellowjackets, native."** It is the German yellowjacket, introduced in North
  America. A nativity correction on the fauna side is its own decision, the
  same shape as *Rudbeckia hirta* was on the plant side (V2.74).
- **One edge makes *Aphilanthops frigidus*, an ant-hunting wasp, a larval host
  on Red Osier Dogwood**, sourced from a mycology portal via GloBI `hostOf`. It
  is almost certainly a misparsed record. It does not reach the `host_plant`
  tag (F120 requires lepidoptera at the far end), and deleting it by hand would
  last only until the next GloBI ingest re-proposes it, so it is recorded here
  rather than removed.

## F156 — the website on a phone, and in a search result

Every item below was measured on the published site at 390 × 844 before, and on
a local build of this branch after, in the same Chromium:

| | published | V2.84 |
|---|---|---|
| `/about/` page width | 821 px (bibliography URLs and DOIs had no break opportunity) | **390 px** |
| First plant on `/plants/` | 1,088 px, below the fold | **519 px** |
| First animal on `/wildlife/` | 754 px | **630 px** |
| The flowering bar on a species page | 147 px (a 12rem label column left it the rest) | **272 px**, its designed maximum |
| SVG console errors per species page | 3 (`height="auto"` is not an SVG length) | **0** |

- **The facet list is a `<details>` rendered open**, and `browse.js` shuts it on
  load below 62rem, the width at which the sidebar already stacks above the
  results. With no script it is simply open, so nothing is lost; the search box
  and the live count stay above it. Verified by tapping: *Filters* opens, and
  ticking the first facet narrows 417 → 311. Desktop is unchanged.
- **The facts table stacks on a phone**, label above value, so a value gets the
  whole width. That makes a species page a little longer on a phone and much
  more legible, which is the trade the flowering bar needed.
- **`height="auto"` is gone** from the three SVG generators (`ecoregion_map`,
  `range_map`, `phenology_bar`); the stylesheet sizes them, and the phenology
  bar, the only one with no CSS rule, has one now. No desktop code renders
  these, so Qt's SVG sizing is not involved.
- **Every page title names the site** (`site_share.page_title`): a search result
  for *Saskatoon Berry (Amelanchier alnifolia)* never said whose page it was.
  Titles that already carry the name are left alone.
- **Every page declares its canonical URL and `og:url`**, added in the one place
  every page is written (`emit` in `static_site_render.write_site`), which
  already knew each path. V2.80 left `og:url` out because threading a path
  through `_page`'s call sites in six modules was the cost; the file writer had
  it all along. Net lines in `static_site_render.py`, which sits five under its
  ceiling: zero.
- **A species description reads as prose and says where the plant is native**:
  *"Saskatoon Berry (Amelanchier alnifolia), native to Alberta and Saskatchewan:
  full sun, partial shade; flowers May–Jun; 26 documented animal
  relationships."* It printed the raw column before, `full sun,partial shade`,
  where the page's own table has always run the value through `_tokens`.

Guarded in `tests/test_static_site.py` over every rendered page (canonical,
title, no invalid SVG height, the foldable facet list, description prose) and
in `tests/test_site_share.py` for the two helpers. The "no external resource"
test gained exactly one exception per page: the page naming itself.

**None of this reaches a reader until the site is republished**, which is F157:
the production build needs the author's Umami ID and feedback URL, and has to
run on the author's machine because the photographs come from its image cache.

## The tests that had stopped testing

V2.83's skip list named four tests that skipped on every machine because the
data had moved:

- **`tests/test_companions.py`, three tests** looked up "Yarrow", which has been
  "Boreal Yarrow" since V2.80 merged *Achillea millefolium* into *A. borealis*.
  The seed data followed the rename; the tests did not. **The companion links
  themselves were fine**, checked before assuming otherwise. The tests now name
  Boreal Yarrow, assert the seeded Saskatoon Berry pair from both sides, and a
  missing seeded plant is a **failure** rather than a `skipTest`, which is the
  whole reason these went quiet.
- **`tests/test_sk_flora.py`** asked for plants whose heuristic `ecoregion` tag
  was a mountain or fescue region; V2.68 cleared those tags, the query matched
  nothing, and the skip message blamed a re-derivation that finished in V2.76.
  Rewriting it against the occurrence-derived regions exercises 26 species, and
  found the old rule no longer holds as stated: *Hedysarum mackenziei* is
  recorded here only in the Rockies and VASCAN, correctly, has it in northern
  Saskatchewan. So the test now checks the rule that survives sourcing: **an SK
  claim the records cannot support must come from the flora**, never an
  inference. All 26 pass, and an `assertTrue(rows)` guard means it cannot go
  vacuous a second time.

The skip baseline falls from 21 to 17 locally (16 on CI, which is not root), so
the CI ceiling tightens from 30 to 25.
