# V2.57 — the last centimetre

**F92 (an order file a nursery accepts) + F91 (ecological substitution).**
*Design principle P8 — repair is more sophisticated than creation.*
*Design principle P3/P10 — relationships matter more than components.*

## What this set out to do

Group D — the professional workflow — was the largest wholly untouched category
on the backlog: four walls a landscape designer hits, none of them about ecology.
With Group B closed in V2.56 it became the obvious next pick, and F92 and F91 are
its two cheap ends.

## What was verified before starting

Everything both features need already existed and was checked, not assumed:
`planting_map.MapKeyEntry` (number, botanical name, form, quantity),
`sourcing.plant_price_range`, `db.nurseries.nurseries_for_availability` and
`access_label`, `db.fauna.fauna_supported_by_plants`, and
`habitat_score.parse_month_range`. All 437 plants carry an `availability_class`;
none is blank.

Two things the survey changed before a line was written:

**"Grouped by supplier" is not derivable.** There is no plant-to-nursery stock
data anywhere in the app — no junction, no feed. What exists is the
`availability_class` enum, which the schema introduced for exactly this
("so a supplier can be matched to a plant's sourcing"), plus
`nurseries_for_availability` to turn a class into real nurseries near the pin.
So the file groups by *channel* and names the suppliers who carry it, which is
true, where "Supplier: Bow Point Nursery" would have been a guess printed as a
fact (P9).

**`openpyxl` is not installed and not a declared dependency.** The backlog said
"CSV/XLSX". CSV is stdlib, opens everywhere, and is what you attach to an email;
XLSX would add a runtime import to a PyInstaller build, which is the class of
change that has broken the frozen Windows build before. CSV only, deliberately,
with a test asserting no such import appears.

## What was decided, and why

### F92

**Numbered from the planting map, not renumbered here.** Line 7 on the order is
plant 7 on the drawing. Two documents that number the same plants differently are
worse than one, and on site that is the whole value.

**Hardest-to-find channels first.** Rare and native-specialist plants need a
phone call; big-box items you collect on the way home. Sorting the file that way
is the difference between a list and a plan of action.

**Database tokens never reach the file.** `native_specialist` is an internal
value; a nursery is sent "Native plant nursery". Guarded by a test.

**The price caveat travels with the file**, not just in the app: the CSV is what
leaves, and the reader is about to spend money against a range (P9).

**No pin means no suppliers, rather than a national list.** The promise is
*near you*; a country-wide list dressed as a local one is the false precision
this codebase keeps removing.

### F91

**"Similar plants" is redefined.** Every other tool means similar height and
colour — a similarity between objects, which is the frame P10 exists to reject.
Here it means same group, overlapping site envelope, and overlapping *supported
fauna*, which is the thing only this app holds.

**The trade is reported, not hidden.** Every line says what the swap keeps and
what it costs — *"Chokecherry for Saskatoon Berry — keeps 6 of 8 supported
species. You lose 2, including Pine Grosbeak, Ruffed Grouse. Adds 6."* A list
that only sells the alternative is asking to be trusted on a judgement it has
not shown.

**Its own group map, deliberately.** `habitat_score.PLANT_TYPE_TO_LAYER` could
not be reused for two independent reasons: it does not cover this catalogue (see
below), and even corrected it would be the wrong grain — grasses and forbs are
both "herbaceous", and swapping a wind-pollinated grass for an insect-pollinated
forb is a bad recommendation however equal their layer.

**Thinly-recorded plants are ranked, not excluded.** Requiring 25% fauna
retention collapses, on a plant with one recorded relationship, into "keep that
exact species" — so the plant would return nothing, punishing the user for a gap
in the *data* rather than telling them about the *plants*. Below four recorded
relationships the filter stands down and the sentence says the comparison is
thin.

## What was found along the way

**F124 — the layer map misses 311 of 437 species, and the Habitat Value Score
reads low because of it.** `PLANT_TYPE_TO_LAYER` knows six `plant_type` values;
the catalogue holds eleven. The missing five include `wildflower` — **210
species, the largest group in the catalogue** — plus grass, sedge, rush, aquatic
and fern. Measured on real designs: **a 12-plant prairie meadow of wildflowers,
grasses and sedges scores 0 of 15 on vegetation-layer diversity.** That is this
app's own central use case, lawn-to-prairie conversion, scoring zero on a
component it plainly satisfies; adding one shrub and one tree takes it to 6.

Reported, not fixed. The correction is a few dictionary rows, but it **raises
the score of every affected design**, and the headline-stability rule reserves
that to the author — the same call V2.53 made about the 48 use tags. F91 works
around it with its own complete map rather than widening the canonical one as a
side effect of an unrelated feature.

**`sun_requirement` is comma-separated.** `"full_sun,partial_shade"` is one plant
tolerating both, and comparing these as whole strings treats it as incompatible
with a full-sun plant. It rejected **76 of 80 candidate grasses** before it was
caught. Tolerance sets must overlap, not match.

**`hardiness_zone_min` can be `'4?'`.** The catalogue records uncertainty in
place, and `int()` on it raised — crashing the feature on the first shrub it was
given. An unreadable zone now reads as "not recorded" and stops constraining.

## How it was verified

40 new tests across two modules, all Qt-free. F92: numbering matches the planting
map, totals add up, channels are ordered hardest-first, empty channels are
dropped, no database token reaches the file, the caveat travels, and no XLSX
dependency appears. F91: wrong group / unsurvivable zone / no shared wildlife are
each excluded independently, tolerance overlap works both directions, `'4?'`
parses, a one-relationship plant still gets candidates *and* says the comparison
is thin, and every `plant_type` in the shipped seed JSON has a substitution group
— read from the JSON rather than the DB, because this module redirects the DB to
an empty temp dir and a skipped guard proves nothing.

Both features were also driven against the **real catalogue**: the order file
produced real Edmonton nurseries at real distances for a real design, and
substitution produced the sentence the backlog imagined, for a shrub, a
wildflower, a grass and a tree.

Full suite: **2967 tests, OK, 98 skipped** (run in halves; the whole suite now
exceeds a ten-minute tool timeout).

## What could not be verified here

The two Qt surfaces — the File → Export order file dialog and the "Find a
substitute…" context menu — were not driven, because this container has no
display. Both are thin: a save dialog and a message box, with the work in
Qt-free modules that are tested. The CSV has never been opened in a spreadsheet.
