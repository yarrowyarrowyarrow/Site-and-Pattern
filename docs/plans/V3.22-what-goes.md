## The reversals (RM-5)

Each of these was a decision someone made on purpose, and the next reader
should meet it as a decision undone, not as code that disappeared.

- **The phone-scan import (V1.62–V1.63) and the Gaussian-splat backdrop
  (V1.65, Spark from V1.77).** Built so a person with a phone scan could put
  their real yard under the design. Reversed because no homeowner on the plan's
  path has a georeferenced point cloud, the import needed four control points
  picked by hand, and the backdrop pulled 5 MB of Spark and a localhost file
  route into every install. What a scan *produced* stays: its buildings were
  saved as ordinary `canopy_footprint` features, which the app still draws and
  shades. The `splat_backdrop` feature is carried untouched, so an old design
  loses nothing on a save (`tests/test_old_scan_designs.py`).
- **The AI path in Generate Design (the LLM spec, with the offline generator
  as its fallback).** Built so a sentence could steer a design. Reversed (G1,
  Y1) because a homeowner cannot install and run a local language model; when
  it was missing they saw the raw error text and their brief was silently
  ignored (R3). The app always builds with the rule-based generator, which was
  already what almost everyone got. `generate_design` stays in the command line
  and the MCP server, whose contract is frozen.
- **The Plant Directory window (F90, V2.41; the start screen's third door,
  moved behind Learn in V2.43).** Built as the catalogue as a reference work.
  Reversed (S4) because since V3.00 it was the same picker and the same plant
  page as Placement › Plants, in a second window. `plant_directory.py` stays:
  the plant page and the website read `species_entry`.
- **The recipe table's reader (`db/recipes.py`).** Dead since the plant-mix
  builder stopped reading recipes; its one call migrated old settings into a
  table nothing read. The table stays.

## Decided, and why

- **The start screen's in-bloom link goes with the Directory.** It opened the
  Directory filtered to this month, so with the window gone it would open
  nothing. Part 04's rebuilt screen drops it anyway; `plant_directory`'s
  `in_bloom_now` and `bloom_line` stay, tested, for whatever shows the month
  next.
- **The brief goes with the AI.** Only the AI read it (07 §PYF-6), and Y1 says
  no brief. The rest of the dialog waits for its rebuild as Plan My Yard
  (PY-1, increment 11); RM-3 only takes out what the AI needed.
- **The installer's exclusions are patterns in the spec, walked by the spec.**
  PyInstaller copies a folder whole, so the spec now walks `data/` and `html/`
  and leaves out what `_NOT_SHIPPED` names; the test runs the spec's own
  patterns and walker rather than a copy of them. Measured: 33.8 MB of tracked
  files left out (32 MB of it `data/fetched/`), plus Spark's 5 MB from RM-2.
- **The "no AI" test reads strings, not docstrings.** RM-3's acceptance says
  "no string"; a docstring is read by a developer, and `errors.py`'s
  ``LLMError`` still describes what the CLI raises.

## Left alone

- `PlantPicker(wide=True)` and `FilterArea(wide=True)` were for the Directory
  window and are now used only by their tests. Taking them out is a
  simplification for the picker's own increment, not a deletion of a surface.
- `src/sprite_gallery_window.py` is off every menu since V3.07 and still runs
  from the command line; only its standalone page left the installer.
- `scene_contract.SCENE_VERSION` is not bumped: the scene lost two keys the
  viewer no longer reads, and an old viewer ignores a missing key.
