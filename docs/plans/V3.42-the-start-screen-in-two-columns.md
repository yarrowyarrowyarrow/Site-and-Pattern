# V3.42 · The start screen in two columns (F259)

*The owner, with three screenshots of the installed V3.41's start screen (its
own size, half the screen, the whole screen): "The opening screen could still
use some work imo … the layout, what is highlighting could use some work. Even
the logo image could be larger … Plan a new yard and your designs should be
'together'. Like Plan a new yard does not have to say 'start from your
address'. Your designs should have an option to 'delete' right underneath
where the 'rename' option appears. Learn about native plants/design, look at
an example yard, and walk a wild landscape should be grouped together in a
simple fashion that leads to these options. It should be elegant like it sort
of currently is. The highlight should probably be on the Plan a new yard
button but maybe 3 things should be highlighted (that, the last design you
worked on and the learning option?" They asked for an analysis and sketches
before any code.*

V3.42 was pencilled in by the [V3.38 plan](V3.38-the-learn-side-and-the-example.md)
for the score and features in the walk (F256). That increment still waits on
the owner's D3 and D5; it takes the next free version, and the V3.38 plan's
branch table says so.

## What the screenshots show

The V3.41 screen was rendered here, offscreen, at the owner's three sizes
with the owner's three designs, and matched the screenshots.

| Seen | Cause |
|---|---|
| Maximised, the name and the tagline sit 100 px apart with the icon between them, and "Your designs" floats in a band of empty ground | The dialog's `QVBoxLayout` has no stretch, so Qt shares a bigger window's spare height out among the labels, nested layouts included (the masthead's name/tagline pair). Its own size was 600 × 485, minimum 399 × 469; nothing stopped it growing |
| The highlighted row reads "From Learn Aspen Parkland grove.perma.g…" | **A bug.** *Take into Design* (`graduation.graduate`) writes the walk's name to `properties.name`; the start screen, the saves list and the title read `properties.project_name`, so `saves.describe` fell back to the file name, extension and all. `.perma.geojson` is in `vocabulary.NEVER`; the ratchet reads source strings, so a name made from data walks past it. The brightest thing on the screen was a garbled file name, which is part of why the highlight felt wrong |
| *Plan a new yard* and the designs are apart | Between them: the example and Learn links, then a rule |
| The three Learn things are on two screens | *Look at an example yard* is on the start screen; *Walk a wild landscape* and *Lessons & Field Study* are behind *Learn about native plants*, a second dialog (`LearnMenu`) |
| No Delete | Only the saves list (*All N designs…*) has one, and it deletes for good with `os.unlink`; its question names the file with its extension and promises a `.bak` copy a homeowner would never find. The saves folder is under `%APPDATA%` |
| The rows' edges do not line up | *Plan a new yard* runs the full width; the design rows stop short of their Rename links |

## Sketches, and the owner's answers

Four sketches were drawn as real Qt widgets in the app's own colours (so they
promised nothing Qt cannot draw): A, one column (Your yards, then a Learn card
below; about 750 px tall with the title bar, which does not fit a
1366 × 768 laptop); B, two columns, Your yards beside Learn (about 540 px
tall); and four highlight rules on B.

**The owner's answers (31 October 2026):**

| | Asked | Answer |
|---|---|---|
| D1 | Layout A or B | **B** |
| D2 | Highlight: H1 last design filled · H2 *Plan a new yard* always filled · H3 *Plan a new yard* filled, the last design and Learn outlined · H4 last design filled, the other two outlined | **H3** (the recommendation was H4) |
| D3 | The Learn items on the screen (the second Learn window retired), or one Learn button leading to them | **On the screen** |
| D4 | Delete to the Recycle Bin after a question naming the design, or for good | **The Recycle Bin**, as recommended, with the saves list's Delete made the same; not offered for the open design or a file kept outside the saves folder |
| D5 | Branch | **V3.42** (V3.41 is released and installed; the updater compares version numbers, so another push to V3.41 would not read as an update) |
| D6 | (the owner's own) | *Lessons* and *Quizzes* are separate items under Learn; every description line starts with a capital letter; the line of what is in flower goes |

**On D2.** The filled row is the dialog's default button: Enter presses it.
The recommendation was to fill the last design, so that a person coming back
does not start a second copy of their yard by pressing the brightest thing.
The owner chose H3 having seen both; it is built as chosen. In H3 the filled
row is *Plan a new yard* in every state but one: unsaved work after a crash,
when the amber *Restore* row is filled and the three doors are outlined.
"Exactly one filled row, and it is the default" stays the tested rule (it
always was a rule about one default, which three filled rows would break).

## What changes

1. **Two columns, centred** (`src/start_screen.py`). The masthead across the
   top with the icon at 80 px (48 before), the name at 30 px. *Your yards* on
   the left: *+ Plan a new yard*, then up to three designs, then *All N
   designs…* and *Open a file…* together. *Learn* on the right: one outlined
   card of four rows. The content is a fixed-width block in a grid with
   stretch on every side, a little above the middle, so a bigger window shows
   more ground around the same screen and never pulls it apart. A Restore row
   spans both columns above them. The footer is the checkbox alone, and no
   rule when there is no checkbox.
2. **A design row says two things** (`start_flow.screen_designs`,
   `saves.card_line`): the name, and under it a line in sentence case, "24
   plants" or "No plants yet", with the short place when the name does not
   already say it; the date stays on the right. The second line is the height
   the stacked Rename and Delete need, and it tells *Test Design* from
   *Building Scan Test*. "species" stays off it (an advanced word, WD-1).
3. **H3** (above). The outlined style is a green border on a slightly lighter
   ground: head text 11 : 1 on it, the line under it 9 : 1.
4. **Learn, on the screen** (`app_mode.LESSONS`, `app_mode.QUIZZES`):
   *Look at an example yard* (A finished front yard), *Walk a wild landscape*
   (Seven native places, in 3D; the number is counted from
   `reference_ecosystem.community_keys`), *Lessons* (Native plants and
   design), *Quizzes* (Plants, animals and seasons). Lessons and Quizzes each
   open the Learn window on their own page, with its own title and no tab bar
   (`LearnStudioWindow(page=…)`); the walk and the example open as before.
   **The Learn menu is retired**: `LearnMenu`, `learn_flow.open_learn_menu`,
   `app_mode.LEARN`, `BACK`, `LEARN_DOORS`, `learn_notes`, and the Learn
   branch of `onboarding_flow._menu_loop`. The window is now
   `src/learn_window.py`; nothing is left in a module named for a menu.
5. **Delete** (`start_flow.delete_design`, `plain_messages.ask_delete_design`).
   Under each Rename. The question names the design ("Move “Back yard
   meadow” to the Recycle Bin? You can get it back from there."; *Trash* off
   Windows), Cancel the default. The file and its one-save backup go to the
   system's bin through `QFile.moveToTrash` (Qt 5.15+; the installers pin
   6.11 on Windows, 6.7 on the Mac). If the bin refuses, nothing is deleted and
   the person is told. Not offered for the design open in the window (the
   screen from Help › Start Screen) or a file kept outside the saves folder
   (`saves.deletable`). The screen stays open and redraws its list, as after
   a rename. The saves list's Delete calls the same function, so it stops
   deleting for good and stops naming the file.
6. **Names** (`graduation.graduate`, `saves.describe`). A graduated walk
   writes `project_name` as well as `name`; a file with no name inside reads
   as its file name without `.perma.geojson` (so the owner's existing
   *From Learn Aspen Parkland grove* lists by that name); `plain_messages`'
   "Couldn't open" says the design's file name the same way.
7. **The line of what is in flower goes** (the owner, D6), with
   `start_flow.flowering` and the screen's `flowering` arguments. This
   reverses V3.23, where the owner asked for it. `plant_directory_bloom`
   now has no caller in the app (its other functions had none since V3.23);
   whether to retire it or use it elsewhere is left as a suggested task, not
   decided here.

## Found while building it

- **`start_screen.py` came out at 410 lines against its ceiling of 380.** The
  guard says to split, not to raise the number: the rows, links, card and the
  two layout helpers went to `src/start_rows.py` (opted in at 280), and the
  screen is 369.
- **A redraw left the old Rename and Delete behind.** Clearing the list hid
  each line's container, which hides its links to the eye but leaves them the
  screen's children (and a screen reader's) until Qt's deferred delete; the
  first rename test found two lists of links. `start_rows.clear_layout` now
  takes each widget out of the window before deleting it later.
- **Two documents claimed what was no longer true.** The in-app guide
  (`data/guide.md`) sent people to *Learn about native plants*, which this
  increment removes; `tests/test_guide.py` checks only the controls it names,
  so the Learn doors are named there now. `docs/UI_PRINCIPLES.md` listed an
  eight-word and a five-word rule as held by `test_start_menu.py`; no test has
  held either since V3.23. The list says what the tests hold.
- **In a wide font a long name was cut mid-letter.** Rendered in CI's DejaVu
  Sans, "8103 95A Street NW (unsaved changes fr" ran into the date: a label
  inside a button does not elide, and the 40-character cut assumed a
  narrower row than two columns leave. The name and the line under it are
  `elided_label.ElidedLabel`s now, ending in "…" at the width they are given,
  the whole name kept in the tooltip; the 40-character cut stays first, as
  before.
- **A count past twelve starts with a figure** ("30 native places"), which is
  not a capital. The rule the owner asked for is that no line starts with a
  small letter, and the test says that; a design's "24 plants" is the same
  case.
- **The real bin is tested on Linux only**, with the data folder pointed at
  the test's own, where Qt honours it (checked here: the file landed in the
  redirected `Trash/files`). On Windows the same test would put files in the
  owner's real Recycle Bin, so it does not run there; every other delete test
  uses a bin of its own.

## Left alone

- **Closing a Learn window opened from the start screen ends the app**, as it
  did from the Learn menu: the design window is built but never shown for a
  learn-only choice, and Qt quits on the last window. Coming back to the start
  screen instead is a reasonable next step; nobody asked for it.
- **The checkbox and Help › Start Screen** work as before.
- **The saves list itself** (its layout, Rename…, Browse…) apart from Delete.
- **F256** (the score and features in the walk): unchanged, still waiting on
  D3 and D5.

## Could not verify

- **The Recycle Bin on Windows.** `QFile.moveToTrash` was run here on Linux,
  where it uses the freedesktop trash; on Windows it is the shell's own call
  and was not run. The fallback (nothing deleted, a message) covers a refusal,
  not a wrong destination.
- **Segoe UI.** The screen was measured in the container's fonts (Inter, and
  DejaVu Sans as CI draws it); Segoe UI is narrower than both, so the screen
  can only be roomier on the owner's laptop.
- **High display scaling.** Two columns make the screen 956 × 490 logical
  pixels where it was 600 × 485 (555 tall with work to restore): about as
  tall, a third wider. That fits a 1366 × 768 screen at 100% and a
  1920 × 1080 one at 150% or 175%. At 200% (960 × 540 logical) it is the
  display's width, and the Restore state is taller than the room above the
  taskbar. Not tried on a real scaled display; a narrow-window layout (the
  columns stacked) would be the fix if it matters.
- **The 3D walk** needs WebGL, which this container does not have; the door to
  it is unchanged.
