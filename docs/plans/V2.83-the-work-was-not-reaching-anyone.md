# V2.83 — the work was not reaching anyone

*A review of where the project stands found that the last seventeen increments
of catalogue work were largely sound, and that the plumbing between that work
and the people it is for had quietly failed in four places. This increment
fixes the four that need no decision from the author.*

## What the review measured

The author asked for a review of the code and the website, and for the real
next steps. The findings that shaped this increment, with the evidence:

| Finding | Evidence |
|---|---|
| **No test suite runs anywhere but inside a Claude session** | `.github/workflows/` holds `release-macos.yml` and `release-windows.yml` and nothing else. Neither runs a test. |
| **So a red test went unseen for three increments** | With PyQt6 installed: 3,696 tests, **1 failure**, 21 skipped. `test_the_flower_colour_filter_narrows_and_restores` asserts `purple + yellow == both`, which stopped being true when `bda0824` (V2.80) let a flower bloom in more than one colour: 61 + 83 − 3 = 141, and the widget correctly shows 141. The V2.82 commit message records *"the 12 errors are ModuleNotFoundError: PyQt6 in this container"*, which is the same condition that hid the V2.33 PDF-export `NameError` for four minor versions. |
| **The design map does not start without the internet** | `html/map.html` loads Leaflet and Leaflet.draw from `unpkg.com` (lines 9–11 and 221–223). Rendered offscreen with no egress, the window opens on an empty dark panel and the console reads `Uncaught ReferenceError: L is not defined` from `01-core.js` and `04-tools.js`. Boundary drawing, placement and every overlay depend on `L`. The 3D viewer vendored three.js and Spark long ago and has a test forbidding CDN references (`tests/test_scene3d_assets.py`); the 2D map, which the whole design workflow runs on, never got the same treatment. The map-frontend skill documented it as a gotcha rather than a bug. |
| **The instructions every session reads were describing a finished increment as open** | `CLAUDE.md`'s "Work in flight (V2.79–V2.80)" section lists three open threads. All three are closed: every one of 417 rows now carries `native_provinces_source = 'flora'`, the four fruit cultivars moved to `data/food_plants_pack.json` in `fd3f5ee`, and the two species VASCAN records elsewhere were dropped in the same commit. The section's own last line says to delete it when the work ships. |

Other stale statements found in the same pass, each checked against the code
or the data rather than against memory:

- `CLAUDE.md` says `WITHHELD_ROLES` keeps `medicinal` off the public web. It has
  been an empty tuple since V2.50, on the author's decision; the free-text notes
  are what stay withheld. README says the same wrong thing.
- `CLAUDE.md` says the V2.80 map swap took a species page to 111 KB and the
  site to 118 MB. The ecoregion map came back below the occurrence map later in
  V2.80, on the author's review; the published build is 328 MB with a median
  species page of 585 KB raw (about 180 KB compressed, which is what a reader
  actually downloads).
- `CLAUDE.md`'s `nativity.py` row still describes 354 species publishing an
  unsourced inference and VASCAN as a seam "a test fails the day it appears".
- README still says 433 plants, "23 axes", and that the region outlines are
  hand-traced. It is 417, the site counts 21 searchable fields, and the outlines
  have been the National Ecological Framework v2.2 since V2.67.
- `BACKLOG.md` still lists as open: asking VASCAN about nativity (shipped V2.80),
  merging the synonym duplicates (V2.80 and V2.82), and publishing the
  occurrence points (F147, V2.80).

## What this increment does

1. **A test workflow** (`.github/workflows/tests.yml`) on every push to a
   `V*.*` branch and on pull requests: the suite with PyQt6, PyQt6-WebEngine,
   rasterio and pyproj installed, Qt offscreen, then `validate-data`.
2. **A runner that reports what the suite actually did** (`scripts/run_tests.py`).
   Two traps from `CLAUDE.md` made a plain `python -m unittest` unfit for CI:
   - With WebEngine installed the process **exits 139 at teardown, after the
     summary**, so the exit code of a green run is a crash.
   - A missing Qt library makes ~156 tests **skip silently**, and a skipped test
     is a pass to CI.

   The runner exits with the result's own verdict before interpreter teardown
   (`os._exit`), and fails the run when skips exceed a stated ceiling, printing
   every skip reason so a new one is readable in the log rather than inferred.
3. **The stale colour test**, rewritten to assert the union the widget is meant
   to show, computed from the query layer by plant id rather than by adding two
   counts.
4. **Leaflet 1.9.4 and Leaflet.draw 1.0.4 vendored** under `html/vendor/`, with
   their licences and a provenance note, and `html/map.html` pointed at them. A
   test pins that `map.html` names no CDN and that every local file it names
   exists. The map tiles still need the network; that is data, not code, and the
   map now starts and draws without them.
5. **The documentation corrections** listed above, and the review's other
   findings recorded as backlog rows so they are not only in a chat transcript.

## How it went

- **The suite, run exactly as CI will run it** (`validate-data`, then
  `scripts/run_tests.py --exclude tests.test_undo_redo --max-skips 30`) on Ubuntu
  24.04, Python 3.11, PyQt6 6.11: **3,703 tests, 0 failures, 0 errors, 21
  skipped**, `RESULT: OK`, exit 0. The runner left before the WebEngine teardown,
  so no 139. That is 3,696 from the review run plus the seven new map tests,
  with the colour test now passing.
- **The map, in the running app with no egress**: before the change the
  offscreen window opened on an empty dark panel with two `L is not defined`
  errors; after it, `L.version` reads 1.9.4, `L.drawVersion` 1.0.4, `map_ready`
  fires, the default marker icon resolves to the vendored file, the console is
  clean, and the map draws with its zoom control on a grey, tile-less ground.
- **The skip ceiling was proven on a throwaway module**: two skips against
  `--max-skips 1` gave `RESULT: FAILED` and exit 1; against `--max-skips 2`, OK.

**What the skip list turned up.** Of the 21 skips, 15 are honest (no Blender,
no Pillow, no pypdf, running as root, a shallow clone, a backend choice). Four
are tests that **stopped testing anything when the data moved** and nobody saw,
which is the failure the skip ceiling exists for, one level down:

- `tests/test_companions.py`, three tests: *"Yarrow not present in seeded plant
  data"*. There is no row called Yarrow since V2.80 merged *Achillea millefolium*
  into Boreal Yarrow (*A. borealis*), so these skip on every machine.
- `tests/test_sk_flora.py`: the skip reason says the derived ranges are
  *"mid-re-derivation"*, which stopped being true in V2.76.

Both are left for their own change, because re-pointing a companion test at a
different plant is a decision about what the test means. Recorded so the next
session does not read 21 skips as 21 missing optional libraries.

## What is deliberately not done here

- **No release is cut by this plan on its own.** Pushing a `V*.*` branch runs
  both release workflows, which publish installers the in-app updater will offer
  to every user. That is the author's call, asked for separately.
- **`tests/test_undo_redo.py` stays out of CI.** It segfaults mid-run in its own
  `tearDown` in a GPU-less environment, identically on a clean tree
  (`CLAUDE.md`, V2.40). A job that is always red teaches people to ignore red.
  It still needs a real desktop.
- **The website fixes, the wasps filed as bees, and the design generator's
  region-scale site matching** were found by the same review and are recorded in
  `BACKLOG.md`. Each changes what users see, so each is its own increment.
- **CLAUDE.md is corrected, not restructured.** It is 60 KB and read by every
  session, and slimming it is worth doing, but moving its content around is a
  decision about how the author wants to work with it.

## What could not be verified here

- **README's old "Known Limitations" list**, removed with its V1-era "Going
  Forward" section. Its six items were not re-checked one by one, so they are
  recorded here rather than dropped: plant names with apostrophes breaking
  JavaScript-rendered components; undo/redo being extended beyond plants; PDF
  export silently omitting the map when a screenshot fails; polyculture
  placement matching lat/lng with a floating-point tolerance; soil data outside
  SoilGrids being incomplete; and the Edmonton open-data download failing on
  field-name detection. The second and fifth are superseded (global undo shipped
  with the undo/redo characterisation suite; the offline soil pack and regional
  fallback shipped in V1.67). The other four are unverified either way.

- **The workflow itself has not run on GitHub.** It was validated as YAML, and
  every command in it was run locally in the same order on the same Python and
  PyQt6 versions. The first push is the first real run.
- **The live domain.** This container's egress policy refuses
  `grownativeplants.ca`, so the site was reviewed from the `gh-pages` branch,
  which is what GitHub Pages serves.
