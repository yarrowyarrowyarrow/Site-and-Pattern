## F131 — the larval hosts the verb could not vouch for

### What was wrong

The ingest gate refused **700** candidate `larval_host` edges with one rule:
the record has to come from GloBI's explicit `hostOf` verb. That rule earned
its place. Without it, V2.59 put 23 false Monarch host edges into the seed —
goldenrod, aster, blazingstar, sunflower, yarrow — because the fetcher's
"life stage unrecorded → larval_host" default promoted adult *nectaring*
records into host claims. Telling somebody to plant goldenrod to host monarch
caterpillars is worse than telling them nothing.

But **unspecific is not false**. `eatenBy` is a vague verb, not a wrong one,
and F128's observations re-fetch (already on disk since V2.62) carries the one
field that separates the two: `_life_stage`, present on 41% of records.

### What the data said

Of the 700 refused candidates, matched against the observation rows for the
same pair:

```
 44  have an observed LARVA on that exact plant
  2  are adult records                          -> nectar
654  have no observation row at all             -> still refused
```

Every recovered edge is checkable against a field guide, and the specialists
are the proof the method works rather than merely adds rows:

| plant | animal | |
|---|---|---|
| Evening Primrose | *Schinia florida* | obligate *Oenothera* specialist |
| Spreading Dogbane | *Cycnia tenera* | the Dogbane Tiger Moth |
| Flat-topped White Aster | *Chlosyne harrisii* | Harris's Checkerspot's host |
| Slender Nettle | *Polygonia interrogationis* | Question Mark, on *Urtica* |
| Bearberry | *Callophrys polios* | Hoary Elfin, on *Arctostaphylos* |
| Bog Cranberry | *Boloria freija* | Freija Fritillary |

**Nothing recovered puts a Monarch on anything but a milkweed.** Asserted now
against the seed file as well as the database, so both would have to fail
before it could ship again.

### Two rules that keep the relaxation honest

**A pupa does not evidence a host.** Larvae of many species wander off the
plant to pupate, so a pupa on a stem is evidence of a stem, not of a diet.
This costs one real edge — a bagworm on chokecherry, which genuinely does host
there — and it is still the right rule, because the rule is what ships, not
the instance. An egg *does* count: a female choosing where to oviposit is
making the host claim herself.

**The adult → nectar reroute is Lepidoptera-only.** An adult butterfly at a
flower is nectaring. An adult *beetle* on a leaf is chewing it, and routing
that to `nectar` would invent a reward out of a record describing damage —
the Monarch bug in a new costume. Both records this currently moves are
*Hemaris thysbe* on bergamot, which is a hummingbird moth doing exactly what
the reroute says.

Anything else — no observation row, a stage nobody wrote down, the bare `"a"`
that appears 12 times — comes back untouched and stays refused. Guessing that
`"a"` means `adult` is precisely the shortcut the whole file exists to refuse.

### The knock-on nobody planned

V2.64's orphan filter withheld 18 admitted animals whose every candidate edge
was dropped downstream, on the reasoning that a fauna row connected to nothing
is worse than no row. Nine of them gained a host edge here, so `writable()`
reclassified them and their rows were written: Freija Fritillary, Waved
Sphinx, Small-eyed Sphinx, Western Tent Caterpillar and five more. Nine remain
unconnected and stay unwritten.

Both guards that caught this were doing their job, and neither was written
with this increment in mind. That is the argument for guards that assert a
*relationship* between two files rather than a count in one.

## F120 — give the score the data the app already holds

### What was wrong

The Habitat Value Score's host and bird-food components read **use tags**. The
citations live in **edges**. Nothing kept them in agreement, so the app held a
sourced `larval_host` record for Chokecherry while `design_critic` told the
user their chokecherry planting has *"no butterfly/moth host plants — without
host plants there are no caterpillars."*

V2.53 measured it at 48 species and deliberately did not fix it: correcting
the tags moves every affected design's score, and the headline-stability rule
makes that the author's decision rather than a side effect of a wording pass.
This increment takes that decision. By V2.65 the gap had grown to **117**.

### The taxon requirement is the part that matters

The first pass read the relationship alone and proposed 101 species. Reading
the receipts caught it:

```
Bee Balm      larval_host  Bombus pensylvanicus   <- a bumblebee
Big Bluestem  larval_host  Melanoplus infantilis  <- a grasshopper
Black Hawthorn larval_host Blaesodiplosis crataegifolia <- a gall midge
Black Spruce  larval_host  Urocerus flavicornis   <- a horntail
Blue Grama    seed_food    Peromyscus maniculatus <- a deer mouse
```

**107 of 346 `larval_host` edges are bees, aphids, horntails and gall midges**,
and three `seed_food` edges name a mouse. A gall midge developing in a hawthorn
is a *true* larval-host record that says nothing whatever about caterpillars —
but `host_plant` is the tag that drives the butterfly/moth sentence.

Same failure as the Monarch, `eatenBy` and nectaring-sparrow bugs: an
unspecific record read as a specific claim. Same answer. `_TAG_BACKED_BY_EDGE`
now carries the taxon that has to be at the far end:

```python
"host_plant": (("larval_host",), "lepidoptera"),
"bird_food":  (("fruit_food", "seed_food"), "bird"),
```

The gate and the fixer read that one table, so they cannot drift — and a
warning that can never reach zero because the fixer disagrees with it is a
warning that stops being read.

That cut 117 to **80 real corrections**, and 95 edges were correctly refused.

### Additive only, and that is a rule

A missing tag beside a cited edge is a contradiction: the app holds a record
it is not counting. A tag with no edge behind it is **not** the mirror image.
Absence of an edge is absence of evidence — the catalogue's edges cover a
fraction of what is real — so removing `bird_food` because GloBI has no record
would delete a human's judgement on the strength of a gap. The same reasoning
that makes an establishment band read `unknown` rather than `unlikely` below
the occurrence floor (P9).

### What it moves

The worked example (14 species) goes from **1/10 host and 4/10 bird** to
**6/10 and 6/10** — **+7 points** on the headline, in the direction the app's
own citations already supported.

### A sentence that can now retire

`design_critic` carries a branch written *because* F120 was open: when a design
has cited caterpillars but no `host_plant` tag, it says *"the host tags are
behind the relationship data, so the score reads lower than the evidence
supports."* That is a workaround apologising for this exact gap. With the gap
closed it should no longer fire — but it is left in place rather than deleted,
because it is still the correct thing to say if the two ever drift again, and
now the data gate would catch that first.

### One thing that went wrong and is worth writing down

The first `--apply` produced a **27,495-line diff for 80 edits**, because the
script wrote `indent=1` and the catalogues are `indent=2`. The fix — read the
file's own indentation first — *still* produced a 27,493-line diff, because
`_indent_of(path)` was being called inside `open(path, "w")`, which had already
truncated the file, so it measured an empty file and took the fallback. Read
the format before destroying it. Final diff: **80 insertions, 80 deletions.**

## F129 — the layer component was measuring the wrong thing

### What was wrong

`CANONICAL_LAYERS` is overstory / shrub / herbaceous / groundcover / vine —
the permaculture **forest-garden** stack. A prairie genuinely occupies two or
three of those. So even after F124 fixed the plant-type map in V2.60, a
correct and complete grassland planting was capped at **6 of 15** while a
woodland-edge design reached 15.

The component was measuring *how much like a forest garden is this* and
reporting the answer as habitat value, in an app for prairie conversion whose
own reference communities are grasslands.

### The fix

The denominator becomes the layers the **reference community** actually has.
`reference_ecosystem`'s specs are already honest about this — Mixedgrass
Prairie and Wet Meadow both declare `canopy: {genera: [], count: 0}` — and
`reference_fidelity.fidelity()` already drops zero-count layers before
scoring. So the question changes from *how woodland-like is this* to *how much
of your place's own structure have you rebuilt*, which is the question P2 says
the app is asking.

**The per-layer arithmetic is not reimplemented.** `fidelity()` already owns
what counts as a layer being present (a 0.25 presence fraction, half credit
for started-but-thin), and it sits three rows above this in the same panel. A
second copy would drift and the two would disagree about one design. A test
asserts the reuse by reading the source.

### What it moves

| design | universal | vs Mixedgrass Prairie | vs Aspen Parkland | vs Boreal Mixedwood |
|---|---|---|---|---|
| grassland (9 spp) | 6.0 | **10.0** | 3.8 | 5.6 |
| woodland edge (9 spp) | 12.0 | 10.0 | 11.2 | **13.1** |

**The change is honest, not generous.** A grassland gains four points on
prairie and *loses* two in Aspen Parkland — where it really is missing the
canopy and the shrub ring that belong. A measurement that could only ever
raise the number would be a compliment, not a measurement.

### Defaults, deliberately

Twelve callers pass no ecoregion and **none of their scores move**: the
universal stack stays the default. Only the Analysis panel, which already
resolves `_site_ecoregion()` for the fidelity band, passes one. An unresolvable
ecoregion falls back rather than scoring zero — no reference is a catalogue
gap, not a design failure (P9).

The score row names its basis (`vs Mixedgrass Prairie`, plus which layers are
thin and which absent). A user seeing 15/15 for three layers has to be able to
tell it was three layers *their grassland actually has*, and not a bug.

## Deliberately not done

- **The other two F129 options.** A grassland-aware universal layer set
  (litter / short / mid / tall / emergent) is a bigger and more interesting
  change, and re-basing onto the reference gets the honest number without
  inventing a second layer vocabulary to keep in sync with the two that exist.
- **Removing use tags with no edge behind them.** See above — that is not the
  mirror image of adding one, and it is not a data fix.
- **The 654 host candidates with no observation row.** They are refused, not
  wrong; a wider observations fetch would settle some of them.
- **The 9 animals still admitted-but-unconnected.** Every candidate edge they
  have is dropped by a gate. Writing them would put nine animals in the
  catalogue connected to nothing.

## What could not be verified here

**3,015 tests pass.** Run per-module with a 180 s cap each, because a single
combined run stalls and then reports nothing at all — which is worse than a
failure, since it names no module.

`test_undo_redo` is excluded for the environmental segfault documented in
`CLAUDE.md`. Four further modules **time out rather than fail**:
`test_llm_design`, `test_learn_mode`, `test_pull_a_plant`,
`test_viewer_controls`. All four were re-run on a **V2.64 worktree** and time
out there identically, so none of it belongs to this increment — that check is
the only reason it can be said rather than assumed.

`faulthandler` names the cause for the first one, and it is worth writing down
because `CLAUDE.md` currently claims the suite is offline:

```
File "src/terrain.py", line 127 in _http_get_json_retry
File "src/terrain.py", line 604 in fetch_openmeteo_grid
File "src/zoning.py",  line  84 in site_elevation_grid
File "src/llm_design.py", line 1204 in _zone_context
File "src/llm_design.py", line 1029 in generate_design
```

The generator is making a **live Open-Meteo call** and blocking on it — one
second of CPU across three minutes of wall clock. `tests/__init__.py`'s offline
guard raises `URLError` for anything past the machine, but this path goes
through a *retry* wrapper, and behind this container's HTTPS proxy the request
hangs instead of failing fast, so the retry never gets its exception. **Not
fixed here** — it is pre-existing, it is test infrastructure rather than
product, and it is its own piece of work. It is the reason the four modules
above are unverified in this environment.

No display, so nothing was checked in a running GUI. The panel rows for F129
were rendered by calling `AnalysisPanel._layer_lines` directly, which proves
the text and not the layout.

The reference-community layer specs are hand-authored, so F129's denominator is
only as good as they are. That is unchanged by this increment, but it is now
load-bearing in one more place than it was.
