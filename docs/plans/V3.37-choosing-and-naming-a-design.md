# V3.37 · Choosing and naming a design

*The owner, with three screenshots of the installed V3.37 (the start screen,
and the saves list over the map): "The opening menu could use another look.
The 'Open a Design' button opens the whole app map page which it shouldn't
until the actual design has been selected. You should be able to rename the
design as well rather than have it just read all the addresses. On a separate
note the term 'mesic' is not understandable to many. It should convey that it
is neither dry nor moist but between the 2."*

## What changed

1. **The list and the file picker open over the start screen** (`onboarding_flow._menu_loop`,
   `start_flow.choose_design`). A design picked there comes back as that
   design, the same string a listed row returns (`path_choice`), so the map
   opens on it; Cancel returns to the screen, as Learn's Back already did.
   Nothing about the window changes: it is still built behind the screen and
   shown once a door is picked. The list opened with no parent carries
   `WINDOW_STYLE` and its own dark stripe (`alternate-background-color`):
   Fusion's palette stripe is near-white, and the app's pale text vanished on
   it. The file dialog is one function now (`start_flow.ask_for_design_file`),
   `MainWindow._ask_for_design_file` delegates to it.
2. **Rename beside each design on the start screen** (`StartScreen(rename=…)`,
   `start_flow.rename_listed`). The screen stays open and redraws its rows; the
   renamed design is written afresh, so it becomes the first row and takes the
   focus; the tab order is put back in drawn order (`_retab`), because widgets
   made after their window join the end of its tab chain. No Rename for a file
   that cannot be read. The list's Rename… and the screen's share
   `start_flow.rename_design`, which also renames the open design in the
   window when it is the one renamed (Help › Start Screen).
3. **One list of your designs** (`saves.your_designs`): the saves folder plus the
   design you were last in when it is kept elsewhere. The screen counts it and
   the list shows it, so the two numbers agree. Delete is off for a design
   kept outside the saves folder ("This design is kept outside your saves
   folder."): deleting a person's file from somewhere else is not this list's
   business.
4. **One date on a kept design** (`saves._KEPT`): the old "(unsaved changes from …)"
   is taken off before the new one goes on, however many an older version
   stacked. Only a date at the end is taken: "Back (and side) yard" keeps its
   brackets.
5. **A name the address gave follows the pin** (`design_name.renamed(current, label,
   previous)`): the pin handler passes the previous pin's label, and a name
   equal to that label's short name is still a placeholder. A name the person
   changed, by a word or a date, is theirs. The same label again (undo
   re-placing the pin, U3) changes nothing.
6. **Where a design is, in a few words** (`saves.short_place`): "10173 144 Street
   NW", left out when the name already says it; the whole address is in the
   tooltip. The list elides rather than scrolling sideways.
7. **A session's own recovery copy goes on a clean close** (`_wrote_autosave`, set by
   `_autosave`): the close guard is now *the check ran, or the copy is ours*.
   The original guard's purpose stands: a window that never got a map cannot
   delete a copy it did not write. A late page load no longer offers the
   session its own copy back either.
8. **"Mesic" is "Medium moisture"** (`polycultures.MEDIUM_MOISTURE`): community rows
   ("8 plants · Full Sun · Medium moisture"), the Moisture filter's choices,
   its group headings, and a tooltip that says "medium moisture (neither dry
   nor wet)". The glossary (`09-words.md` §2, `vocabulary.GLOSSARY`) puts
   *mesic* under Never.

## Decided, and why

- **"Medium moisture", not "between dry and moist".** The scale the app
  computes is Dry · Mesic · Wet, from the plants' water need low · medium ·
  high, so the middle sits between dry and *wet*. "Moist" is the everyday
  word closest to what *mesic* means (moderately moist), so "between dry and
  moist" would put the label beside the wrong neighbour. *Medium* is what the
  plant list's Water filter already says for the same value (one name for one
  thing, WD-1), and what nurseries print.
- **Rename stays a visible word on each row, not a right-click menu or a
  hover icon.** Neither of those can be found by someone who does not know
  to look, and the hover icon cannot be reached by keyboard.
- **Designs are still named from their address** (the owner's S9, ST-5). The
  ask reads as "and let me change it", not "stop naming them". If it meant the
  latter, it is a one-line change in `start_flow.name_from_pin`, and the
  owner's call.
- **Delete stays in the list only.** Not asked for on the screen, and a
  destructive control beside every row of a front door is the wrong trade.

## Left alone

- The kept copy's name still ends "(unsaved changes from 24 Oct)", and the
  screen cuts a long name at 40 characters, so "8103 95A Street NW (unsaved
  changes fro…" still reads that way on the owner's machine until renamed.
  Splitting the date out into the note column would mean parsing names.
- The designs already on the owner's computer keep their stacked names; Rename
  mends them. The cycle that made them is what is fixed.
- `search_plants(moisture="mesic")` keeps its internal key: no person reads it.
- The saves list's "5 species" (the glossary keeps *species* to the advanced
  app) is not in a simple-app module the vocabulary test reads; noted, not
  changed here.

## Not verified

- The screens were drawn offscreen in the container's font (Inter), not on the
  owner's Windows laptop in Segoe UI; the start screen is now at least 600 px
  wide, so the Rename column has room at 1366 × 768.
- The recovery-copy cycle is reproduced against the controller with a fake
  window and read off `closeEvent`'s guard, not by crashing a real session.
