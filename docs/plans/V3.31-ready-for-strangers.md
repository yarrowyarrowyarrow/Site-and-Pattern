*The owner: "Do the next increment." That is the homeowner plan's increment 14
([11-work-plan.md](../homeowner/11-work-plan.md#increment-14--v331--ready-for-strangers-must-about-13-developer-days-f242),

**Done when** (the work plan's line): the README and the release notes show the
SmartScreen and Mac steps; every service is credited; Send Feedback needs no
account; the guide is in the README. All four hold. One question is the owner's

## What was there

- **The release notes already had the install steps.** Both workflows' `body:`
  carried *More info → Run anyway* and the macOS 15 *Open Anyway* path since an
  earlier release. FN-3 and FN-4 (unsigned, with instructions: decisions D2, D3)
  were half done; the README had none of it, and said only "a standalone Windows
  installer is available".
- **Seven User-Agents.** `http_utils` said `PermaDesign/1.0`, and five modules
  wrote their own copy of it (OSM, both tree detectors, the generator's
  elevation fetch, the soil pack); the map's tile requests went out as
  QtWebEngine's Chromium string, which names nothing. Nominatim's policy asks
  for an identifying agent and at most one request a second.
- **The address box searched as you typed.** `_on_address_text_changed`
  started a 600 ms debounce into Nominatim on every pause, which is what the
  Nominatim usage policy forbids by name (autocomplete). Since the press of
  Find already searched, the typeahead was only cost.
- **No list of services.** *Where This Data Came From* credited the catalogue's
  works and photographs; the live services (Open-Meteo, SoilGrids, Overpass,
  Esri, the canopy map) were credited in README prose and nowhere in the app.
  The map's satellite credit read `© Esri` alone.
- **Send Feedback needed a GitHub account.** Its only button built a prefilled
  new-issue link.
- **No third-party notices.** The spec shipped `LICENSE` (V3.18) and nothing for
  Qt (LGPL v3, which asks for its text to go with the program), Leaflet, three.js
  or the Python libraries.
- **The build was not pinned.** The Windows job ran on `windows-latest` with
  `python-version: "3.11"`, and every `pip install` ran with `-q`, so no log said
  which PyQt6 or numpy a release carried. The V3.30 Windows log showed only the
  image (`windows-2025-vs2026`), Python 3.11.9 and PyInstaller 6.22.3.

## What changed

**FN-5, every service credited.** `src/services.py` is one table: name, hosts,
what it is used for, its credit or licence, and what the app sends it. *Help ›
Where This Data Came From* lists it under "Services the app asks while you use
it", and *Help › About* ends with `services.PRIVACY`, one paragraph of what
leaves the computer. `tests/test_services.py` reads every host a URL in `src/`,
`html/map.html` and `html/map/*.js` names and fails on one in neither `SERVICES`
nor `NOT_ASKED` (links, the website's own references, the CLI-only AI), so a new
service cannot arrive uncredited. The Esri entry covers both basemaps it serves
(the default street map is Esri's World Topographic Map, which the README
never said).

**FN-6, one identity.** `http_utils.user_agent()` is
`SiteAndPattern/<version> (+https://github.com/yarrowyarrowyarrow/Site-and-Pattern)`,
the version from `app_version.running_version()` ("dev" without one). The five
copies import it; the map's web profile is given it (`setHttpUserAgent`), so tile
servers see the same name. Address search happens on Find or Enter only, and
`geocode_address` keeps the last 64 answers, so pressing Find twice asks once.
The cache is skipped when its size is 0, which `test_address_search` sets: those
tests ask one address with several replies.

**FN-2, notices.** `scripts/write_third_party_notices.py` writes
`THIRD_PARTY_NOTICES.txt` (195 KB, committed): fifteen components with what each
does and its licence, then the texts, read from `html/vendor/*/LICENSE` and each
installed package's own licence files, a text identical to an earlier one
written once. three.js's MIT text is in the script, since the vendored files
carry only its header. Versions are not written for the Python packages: the
build installs its own, and `build-versions.txt` says which. `--check`, run by
`tests/test_third_party_notices.py`, fails when a requirement or a
`html/vendor/` folder is not named. The spec ships the file beside `LICENSE`.

**FN-12, the build pinned and recorded.** Both build scripts run
`pip freeze > build-versions.txt` and `pip --version >>` after installing,
print it into the log, and the spec bundles it. The Windows job runs on
`windows-2025` with Python `3.11.9`, the macOS job's `PY_VERSION`. **Not
pinned:** a constraints file of exact versions. Part 10 §9 asks for the versions
of *the release that passed the usability sessions*, which is increment 15's;
the first `build-versions.txt` from CI is what that file will be made from.

**FN-3, FN-4, FN-11, the guide.** The README opens on *Get started*: where to
download, the SmartScreen and *Open Anyway* steps, the five steps (find your
yard, outline a bed, Plan my yard, the Overview, Export PDF) with their real
button names, *not an identification guide*, what leaves the computer, and
feedback. The release notes carry the same five steps and lines, one body in
both workflows (a test keeps them equal, since whichever job finishes last
writes the release). *Help › How to Plan Your Yard* opens the README at the
guide's heading (`feedback_flow.GUIDE_URL`, a test computing GitHub's anchor
from the heading). No screenshots: part 10 §8 wanted a picture per step for the
website, which G5 put off, and a README picture of a warning dialog would be one
more thing to go stale.

**FN-8, feedback without an account.** The dialog's last row is *Copy message*
(the subject and body, details included, ready to paste anywhere), *Open in my
email…* (a `mailto:` link, shown only with an address) and *Report it on
GitHub…*. The address is `data/edition.json`'s `feedback_email`, read by
`region.feedback_address()` (region.py is the file's only reader), and **it is
empty**: part 10 §7 says a dedicated mailbox, not the owner's own, and which one
is the owner's choice. Until it is set, the dialog offers the copy and GitHub,
which a stranger without an account can still use only by pasting the message
somewhere the owner reads. Setting the address is a one-line edit and needs no
code.

**D4, Esri's terms.** Could not be read from this session: `arcgis.com` and
`developers.arcgis.com` do not resolve here. A search found that the World
Imagery item is under the Esri Master License Agreement, that the item says it
is *not intended to be used to export tiles for offline*, and that Esri's
developer documentation asks for **"Powered by Esri"** plus the data's sources on
a map showing its basemaps; the imagery's usual credit line is "Source: Esri,
Maxar, Earthstar Geographics, and the GIS User Community". Whether direct tile
use without an ArcGIS account is permitted for a free app could not be
confirmed: the only sources were forum posts that disagree. So the map now
says "Powered by Esri" and the imagery's credit line on both Esri layers, and
the question stays the owner's (and the runbook's yearly check, part 10 §10).
`tree_detect.py` reads imagery tiles for one yard at a time, on request, which
is not an offline export, but the same unconfirmed question covers it.
