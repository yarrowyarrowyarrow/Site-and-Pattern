## Decided, and why

- **The flowering line names plants, and only showy, buyable Edmonton
  natives.** The old footer said "41 species flowering now, catalogue-wide".
  The owner asked for "a little line", and the data led with grasses and pond
  plants (Buckbean, Needle and Thread Grass) in May. It now reads the reviewed
  Edmonton list (F220), leaves out grasses, sedges, rushes and plants that need
  standing water, and names garden-centre plants first: "In flower around
  Edmonton in July: Blanketflower, Boreal Yarrow and 105 more." In December it
  says nothing rather than "0" (P9). It is text, not a link: the Plant
  Directory it used to open went in V3.22.
- **Restore is offered only at launch.** From Help › Start Screen the autosave
  is the running session's own, and restoring it would mean nothing.
- **A suppressed screen opens the last design (S8)**, and only when there is
  one; the box is offered only then too.
- **"My yard" is not a placeholder.** It is what the save prompt suggests, so a
  design saved under it was named by a choice, and a later pin does not
  rename it.
- **File › New keeps its method.** `_on_new` lost the name prompt and now says
  whether it reset, so `start_new_yard` wraps it and MainWindow's method count
  (a guarded ceiling) does not grow.
- **The double-click.** Leaflet's own double-click zoom ran before the app's
  handler, which only finished the outline. It is off, and the app's handler
  zooms by the scroll step when no tool is armed. The probe could not show it
  by reading the zoom (headless Chromium runs no animation frames that late),
  so it counts calls to the map's zoom per double-click.

## Left alone

- Help › Check for Updates is the only way to check now; the screen's footer
  link went with Option B's design.
- `learn_menu.py` borrows the screen's row and lost its emoji with it; its rows
  are otherwise unchanged.
- The saves dialog is not restyled; it gained Rename… only.
