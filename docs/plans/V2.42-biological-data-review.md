# V2.42 — Biological data review: gaps, citations, and what has to be enforced

## The ask

Review the biological data: where the gaps are, and where the citations and
sources are for what we do have. Flora↔fauna relationships in particular. The
stated stakes: *"I need them to know that the data is legitimate but also not
theft."*

That is two different questions with two different answers, and separating them
was the most useful thing this review did.

## What was measured

Every count in `docs/DATA_AUDIT.md` was computed from `data/*.json` directly
rather than carried over from `DATA_GAPS.md` or `DATA_SOURCES.md` — which turned
out to matter, since two of those documents' claims are wrong (below).

The suspicion in the ask was that the flora↔fauna relationships are thin on
sourcing. **That is not what the data says.** All 361 edges carry a real
bibliographic citation naming one of six real works; none is a `"literature"`
placeholder; all 361 plant and fauna names resolve against the catalogues. On
the "is it legitimate" axis, the relationships are in better shape than the
morphology attributes, where all 434 flower and 100 fauna records are the
seeder's estimate with zero citations.

The real finding is elsewhere: **the sourcing is invisible and unenforced.**

- `plant_fauna.source` reaches the view model and is dropped by every widget.
  The user sees photo credits and weather/soil sources; the ecology itself is
  uncited on screen. The data supports the conclusion the user wants their users
  to reach, and gives them no way to reach it.
- `validate_all()` has never opened `plant_fauna_master.json`. 361/361 sourced
  is an accident of how it was authored, not an invariant. Nothing would catch
  the next bulk add arriving bare.
- `src/db/relationships.py:180` hardcodes `evidence="documented"`, so a cited
  Monarch↔milkweed record and an **uncited companion-planting folk pairing read
  identically**. The companion tables have no sourcing columns at all. The most
  folklore-prone data in the app carries the app's strongest provenance claim.
- None of the six cited works appears in `docs/REFERENCES.md`, which
  `DATA_SOURCES.md` points at for exactly this purpose. REFERENCES.md is 129
  lines of design-philosophy books with no floras and no entomology.

## Corrections to existing docs found while measuring

Recorded here because both would otherwise be inherited as true:

- **`DATA_SOURCES.md:49-52`** says the gate enforces credits for
  `plants.image_url` via `validate_fauna_images`. That function filters
  `taxon != "bee"` over `fauna_master.json` and never touches plants. The plant
  photos are in fact clean — 323/323 attributed and licensed — but by authorship,
  not by enforcement.
- **`DATA_GAPS.md:90`** says every one of the 434 leaf records reads `estimated`.
  `leaf_data_source` is **absent from all 434**, so a reseed writes the schema
  default `''` and the validator's error branch can never fire.

A third, smaller one: the `_sources` header inside
`plant_fauna_master.json` declares four works; six are used. Packer, Pattie &
Fisher, and Acorn's *Bugs of Alberta* are cited on 47 edges and declared nowhere.

## What is genuinely strong, and should not be re-litigated

The photo pipeline already answers "not theft" properly: a CC whitelist, a
stricter CC0/CC-BY bar for bees, one shared `credit_line` formatter, a 3D
inspector that asserts the credit is not optional, and a build error on an
uncredited non-CC0 photo. 0 unattributed and 0 unlicensed across 381 images.
`plant_ecoregions` is the schema model the rest should copy — `occurrences` +
`confidence` + retrieval-dated `source`, all `NOT NULL`. And `DATA_SOURCES.md`
carries a worked copyright position (*CCH Canadian*, *Feist*) on reading facts
out of a flora, which is more diligence than most projects of this size manage.

**The "not theft" question is already answered well. It is answered in a file no
user will ever open.**

## Decision: ship the review, hold the app changes

This increment commits the audit and this plan, and stops there. The four
follow-on parts below were scoped and costed during the review but change either
the schema or what the user sees, and that is the author's call to make rather
than a reviewer's. They are recorded so the scoping is not lost.

**Part B · Make the citations checkable** — `data/sources_master.json` with the
six works as canonical keys; normalize the 11 edge strings (and 1 bee / 4 lep
strings) onto them; give `docs/REFERENCES.md` its first biological-sources
section; fix the two inaccurate lines above. The one string that cannot be
normalized honestly is `"Prairie-composite pollination literature; Acorn &
Sheldon 2006"` — its 16 edges keep the Acorn & Sheldon key and lose the
unattributable half.

**Part C · Enforce it** — `validate_plant_fauna()` (every edge sourced, source
resolves to a known work, relationship in the enum, names resolve — turning the
seeder's silent `continue` at `src/db/plants.py:1137` into a build error);
`validate_plant_images()`, the check `DATA_SOURCES.md` already claims exists;
`validate_safety_provenance()` for the 49/49 that currently comply by habit;
and move `_provenance_gap` into `scripts/_bench_common.py` so `tune_fauna.py`
gets the guard `tune_morphology.py` has.

**Part D · Stop the `evidence` claim being a lie** — three states rather than
two: `documented` (in a table *and* cited), `recorded` (in a table, uncited),
`derived` (computed). One line in `_edge_from_row`. Add `source`/`notes` to both
companion tables and stop the view hardcoding `''`. Leave them unpopulated —
an empty source reading `recorded` is honest; a blank one reading `documented`
is not. Requires a schema bump (60 → 61), as does the seed normalization in B.

**Part E · Let the user see it** — the smallest slice of F12.
`src/plant_directory_window.py` already holds `r["source"]` in `_range_block`,
`_wildlife_block` and `_companion_block` and already has the
`_section(…, dim=True)` renderer and a *"Where these numbers came from"* block.
This is display, not plumbing. Plus a Help → "Where this data came from" screen
rendering `DATA_SOURCES.md`, which is the direct answer to "not theft" and today
is reachable only by reading the repo.

## Deliberately not doing, with reasons

- **Materializing genus-level derived edges.** 69 bees carry
  `floral_host_genera` and `src/bee_habitat.py` already infers from them at
  runtime for one panel; promoting those to real edges would lift graph coverage
  well past 22.6% without inventing a claim. But it moves the Habitat Value
  Score and the "hosts N caterpillars" labels, so it needs the three-state
  `evidence` from Part D underneath it and a decision about whether derived
  edges count toward headline numbers. Its own increment.
- **Page-level citation for the 361 edges.** The strongest possible answer to
  "is this legitimate", and it means re-opening six books — not work that can be
  done from this repository. If it is wanted, the 31 **specialist** edges are
  where to start: they carry the most scoring weight and drive the specialist
  spotlight.
- **The two duplicate scientific names** (`Geum triflorum`,
  `Valeriana sitchensis`) — known, already flagged in `docs/review.md:131-137`,
  orthogonal to sourcing.

## What could not be verified

The **contents of the six works**. This review read citation strings and their
internal consistency, not the books. If an edge's claim is factually wrong,
neither this audit nor the enforcement proposed above would catch it. The goal
throughout is to make each claim *checkable by someone holding the book* — not
to certify it. That distinction should survive into any UI copy: the app can
honestly say where a claim came from, and should not imply it has been
independently confirmed.
