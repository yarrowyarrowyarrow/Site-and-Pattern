# V2.53 — the confidence block, and the absence the app could not support

Group A from [`BACKLOG.md`](../BACKLOG.md), chosen by the author: **F8, F12,
F13, F14, F28** — five cards the roadmap has called "really one job: say how
sure we are, and say who says so," named as next and then skipped for twelve
consecutive increments.

Built as one increment rather than five, because done apart each invents its own
words for the same idea and the app ends up with four scales that cannot be read
against each other.

---

## 1. The spine: `src/confidence.py`

One Qt-free vocabulary. It owns two things and deliberately not a third.

**Bands** — the three-plus-unknown scale, with the words for each rung per
context. It does **not** own the thresholds where a domain already has them: the
establishment band's floors come from `ecoregion_ranges.CONFIDENCE_BANDS`, which
sets them against record counts and documents why. Restating them here would
create the second source of truth the module exists to prevent, and a test
asserts the two agree.

**Marks** — one table over the two provenance vocabularies already shipped: the
edges layer's `documented / recorded / derived` (V2.42) and the seed data's
`measured / flora / photo / checked / name / epithet / estimated` (V2.35–V2.48).

Two rules are structural, and both are things the codebase had got wrong before:

- **Absent is not estimated.** A blank field means the app knows it does not
  know. `estimated` means a genus default *was* written in and looks exactly
  like a measurement — the more dangerous of the two because it is invisible,
  and the one that put a red flower on the blue columbine. Different marks,
  different words, and `Mark.inferred` is the flag a UI branches on.
- **A band needs evidence.** Every scorer in this codebase degrades to a neutral
  0.5 on missing input — `score_cell_for_plant` says so in its own docstring —
  which is right for ranking and catastrophic for reporting. `known=False`
  yields `UNKNOWN`, not a middle band. This is the V2.51 bug (`ecoregion_map`
  printing a fabricated "medium confidence" about regions it had no data on)
  turned into a guard.

A third rule sits in `annotate()`: **a verified value carries no mark.** Marking
everything trains the eye to skip the mark, which loses the one case that
matters.

## 2. F8 — the finding was not loose wording

The audit was run before anything was written, and the result was not what the
card assumed. Grepping the ten prose generators for deterministic phrasing found
**five** uses of "will", all innocuous. The app is careful where it was built
carefully: `phenology` says *"we predict"*, `plant_impact` says *"no **documented**
wildlife depends on"*, `docent` says *"**documented** wildlife species"*.

The failure was narrower and worse. **`design_critic` asserted absences as
facts** — *"Nothing provides bird food (berries/seeds)"*, *"No butterfly/moth
host plants"* — and an absence is the one claim incomplete data cannot support.

Then the measurement that made it concrete. Those lines read a zero in a score
component fed by **use tags**. The app holds a second, cited source for the same
question — the `plant_fauna` edges — and they disagree:

| | |
|---|---|
| Species with a documented `larval_host` edge and no `host_plant` tag | **37** |
| Species with a documented `fruit_food`/`seed_food` edge and no `bird_food` tag | **11** |
| Among them | **Chokecherry, Balsam Poplar, Red Osier Dogwood, Bur Oak, Paper Birch** |

So the app could tell a user their design has no caterpillar host plants while
holding 116 cited larval-host records, some of them landing on the very plants in
front of them. And the contradiction is visible **inside a single dictionary**:
`components.host.score` is tag-derived and can be 0 while `food_web.caterpillars`
— two keys over, edge-derived — is True.

**The fix, and what was deliberately not fixed.** `critique_lines` now reports the
stronger source when the two disagree, and phrases every remaining absence as an
absence of *record*. The **Habitat Value Score is untouched**: correcting the 48
tags is a seed-data change that moves every affected design's score, and the
generate-design skill's stability rule says a score movement is a decision to
take deliberately rather than a side effect of a wording pass. It is now a
tracked number instead of an invisible one —
`data_quality.validate_use_tags_against_edges` reports it as a warning in the
gate, on the same principle that turned "0 species have a habit shot" from a
feeling into a figure in V2.35. **Correcting the tags is a real next step and
belongs to the author.**

## 3. F12 — the citations reach the design side

`src/citations.py` shipped in V2.42 with a real formatter and two honesty rules,
and reached exactly two screens: the plant-directory species page and Help →
Data Sources. Neither is where a design is made.

- **The 3D dossier card** now carries a short citation per wildlife row
  ("Acorn & Sheldon 2006") plus a collapsible full reference list per plant.
  `scene_dossier` builds it; `10-inspect.js` renders it. An unattributable edge
  gets **no** citation rather than a placeholder dressed as one, and the count of
  unattributed edges is reported rather than hidden.
- **The relationship web's summary** names the works the picture rests on. The
  V2.42 audit found all 361 edges properly cited and not one citation visible;
  the count of documented edges was as far as the honesty went. A web resting on
  one work is a different object from a web resting on six.

`_source_block` deliberately mirrors `plant_directory_window._citation_block`
rather than inventing a second way to say the same thing.

## 4. F14 — the card proposed a false readout, and it was not built

The card said: bucket `placement_score.score_cell_for_plant` into three bands.
**That would have printed confidence about nothing**, for a reason worth writing
down because it generalises: `build_cell_env_map` fills every grid it cannot read
with `shade=0.5, elev=0.5, slope=0`, so on a site with no DEM fetched *every*
plant scores the same neutral 0.5 and a naive bucket reports "medium" for all of
them. Correct for ranking cells against each other; meaningless as a statement.

So F14 reads the strongest evidence the app actually holds about whether a
species grows in a place: the **georeferenced occurrence records** seeded at
schema v59/v60, which already carry a count, a confidence band and a source per
(species, ecoregion). Saskatoon Berry's parkland claim has 312 records behind it.

Two decisions:

- **Unknown is not "no".** Below the three-record floor, a species that is absent
  and one nobody has collected are indistinguishable. Both get `UNKNOWN` and a
  sentence naming which question is open. Printing "unlikely to establish" over
  an under-collected region would invent a fact and steer a real planting away
  from a species that belongs in it.
- **The design summary takes the weakest well-evidenced rung, not an average.**
  A design is as established as its shakiest species, and averaging lets forty
  well-recorded natives hide the one nobody has ever collected here.

## 5. F13 — fidelity scores structure, not species

F50 shipped the reference community you can walk; this is the number beside it.

Matching the reference species-for-species is neither possible on a suburban lot
nor desirable — the reference is a hectare of parkland, the design is a front
yard. What transfers is the *shape*: is there a canopy, a shrub ring, a
forb-grass matrix. So the score is per-layer presence and proportion, with genus
overlap as a capped bonus, and `PRESENCE_FRACTION = 0.25` — four aspens is a
canopy on a suburban lot even though the reference grove has forty.

**Low is not a failure**, and the blurb says so. A rain garden, a pollinator
strip and a hedgerow are all deliberately unlike their reference. A score that
only ever scolds teaches nothing.

`LAYER_TYPES` is asserted equal to `reference_ecosystem._LAYER_TYPES`, because
two layer maps that drift apart would make the score and the walkable reference
disagree about the same design.

## 6. F28 — one provenance vocabulary, three surfaces

`plant_directory._provenance` printed the raw database token — "Flower detail:
estimated" — which is honest and unreadable; it does not tell a reader that
nobody has ever looked at that number. Both it and `_bloom_colour` now render
through `confidence.mark`, so the desktop directory, the **website** (which
renders the same `species_entry`) and the 3D dossier cannot drift apart the way
the four edge tables did before F7. The local `_COLOUR_SOURCE_WORD` table is
gone; its wording moved into `MARKS` intact, so the V2.48 tests still pass
against it.

## 7. Surfaced

A **"How sure are we?"** block on Analysis → Habitat, above the relationship web.
Both bands, each with its label, the sentence saying what it rests on, and the
detail lines. It refreshes from `set_placed_plants` rather than from the score

## 8. Two things a green test suite did not catch

Both found by running the finished modules against a **real seeded catalogue**
rather than against fixtures, on a plausible six-species parkland design. Both
were in F13. Recorded because the lesson is about the fixtures, not the bugs.

**The genus match never matched anything.** `resolve_reference_community`
appends `r["common_name"] or r["scientific_name"]`, and every seeded row has a
common name — so the reference layers hold *"Saskatoon Berry"* while a placed
plant is matched on *"Amelanchier alnifolia"*. Comparing the first token of each
found nothing, on a design built entirely out of the reference community's own
species, and the read-out said *"None of its characteristic genera are in the
design"* about a yard containing five of them.

It passed its unit test because **the fixture used scientific names on both
sides** — the failure mode a fixture written by the person who wrote the code
always has. Matching is now over both name forms on both sides (`_tokens`), and
the fixture holds common names because that is what the real resolver returns.

**The bonus could lift a design past its own blurb.** With the match fixed, that
same six-plant design scored 0.68 and banded *"Close to the reference"* — whose
blurb reads *"most of the layers … are represented"* — while three of its four
layers were thin or absent. The species bonus had carried it over the threshold
on its own. A band is now demoted when more than one layer is missing, and the
**reported score is clamped with it**, because `score: 0.68` printed beside
`band: medium` is a contradiction a caller has to resolve for themselves.

Two regression tests pin both, and the second is written against the property
rather than the number: *the band never contradicts its own blurb*.

## What was deliberately not done

- **The 48 use tags were not corrected.** It moves scores; it is the author's
  call. Measured, reported in the gate, and written up as a backlog row.
- **The Habitat Value Score weighting is unchanged**, per the stability rule.
- **No new confidence badge on the plant browser.** `plant_panel.py` is at its
  1600-line ceiling and the directory already carries the provenance line.
- **F14 does not use `placement_score`.** See §4 — that was the card's proposal
  and it was rejected on evidence.
