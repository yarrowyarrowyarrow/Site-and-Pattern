# V2.55 — say what the number means, and let go of the mistake

**F122 (the Site Info glossary) + F104 (sandbox undo and the graduation path).**
*Design principle P5 — perception is constructed, not received.*
*Design principle P13 — a native planting has to be loved to survive.*

## What this set out to do

The user picked **Group E, the Learn side**. Group E is seven items and cannot be
one increment: three are L-effort and two of those are blocked on things that do
not exist in the repository — **F85** needs mascot art ("there is no caterpillar
drawing in this repo in any format") and **F107** "wants a conversation about the
template before any code". **F83** is blocked on the `habit` and `leaf` photo
slots being filled. That leaves the two the backlog itself singles out: the
glossary, marked *"do this first, and separately"*, and **F104**, whose first
half it calls *"the embarrassing one"*.

They belong together because they are one complaint: **the side of the app built
for people who do not know what they are doing yet explained nothing and forgave
nothing.**

## What was measured before deciding

Four claims checked against the tree rather than against the backlog. One was
wrong in the direction that matters:

| Claim | Reality |
|---|---|
| "~12 of ~20 Site Info metrics have no explanation" | **15 of 20.** Exactly five rows carried a tooltip: GDD, frost window, ecoregion, aspect, prevailing wind |
| `climate.zone_description()` is uncalled | Confirmed — defined at `climate.py:96`, no caller anywhere in `src/` |
| The GDD₅ explanation is a developer comment | Confirmed — `climate.py:112–124`, unreachable by any user |
| Learn mode has no undo | Confirmed, **and the code says so itself**: `scene3d_edit_flow.py` carries a Design-vs-sandbox table whose sandbox row reads `undo: none` |

Two things found in passing shaped the work more than the backlog rows did.

**The existing tooltips were on the wrong widget.** All five sat on the *value*
label. `addRow("Zone:", w)` builds the caption implicitly, and nothing had ever
put a tooltip on it — so hovering the number explained itself and hovering *the
word you do not understand* did nothing at all. `labelForField` is how you reach
it, and it must be called after `addRow`, not before.

**Graduation was nearly free, and the architecture had said so years earlier.**
`main.py` builds MainWindow even in Learn mode and simply never shows it:
*"it is what the Learn windows hang their singletons off, and **it makes stepping
into Design later instant**"*. So the door out is a coordinate transform, a save
and a `show()` — not a new window.

## What was decided, and why

### F122 — the glossary

**One Qt-free `src/glossary.py`.** Qt-free because F85's companion is meant to
read these out later, and a table locked inside a widget can be shown in exactly
one place. `climate.zone_description()` finally gets its caller; the GDD₅ comment
becomes text a user can reach.

**The three inline tooltips were deleted, not left alongside.** Two sources for
one string is how they drift. A test now fails if any of them reappears.

**The zone's explanation is refreshed where the value is measured**
(`_on_hardiness`), not set once at construction. Set at build time it would name
a winter that is not yours — the failure mode that reads as working.

**Both widgets get it.** That is the whole feature.

**Scope is site physics only (P12)** — cold, warmth, water, wind, ground. No
plant-use content, and a test enumerates the vocabulary that must not appear, so
the constraint is mechanical rather than remembered.

### F104 — undo, and the way out

**The seam, because the window was full.** `reference_ecosystem_window.py` was at
**450 lines against a 450 ceiling** with nowhere to put a button, and the seam its
guard comment had named in advance was taken by the V2.44 split. The new seam:
**the edit bar moved into `reference_edit_flow.py`** — the module that owns what
the buttons *do* now owns what they look like. The window dropped to 409. The
flow's own ceiling went 260 → 320, documented, with the next seam named
(`build_tools` is presentation, not handling).

**`undoable` could not be reused, but its mechanism could.** The decorator reaches
`self._main._persistence` and the sandbox window is not MainWindow. What
transferred is the good idea inside `PersistenceController._capture_state`:
snapshot features as **one canonical JSON string** rather than a deepcopy tree,
because features *are* JSON. The sandbox is literally a `FeatureCollection` on
disk.

**Reset is undoable, and that is the point.** Throwing away every edit was one
click with nothing behind it.

**Undo restores in place.** The window, the viewer bridge and the store all hold
the same dict; rebinding a new one would leave them pointing at the old
landscape.

**Graduation carries the site data across.** This was a bug caught while wiring
it: `_load_from_path` replays `site_config` to restore the pin and every Site
Info reading, so a graduated project without it would open at the right address
with the whole panel blank — and would overwrite the site data the user already
had. It is copied, not aliased.

**Graduation goes through `_load_from_path`**, the app's own File → Open path,
rather than assigning `main._project`. That is what makes a graduated landscape
an ordinary design — rendered, undo cleared, remembered — instead of a special
case.

**The centroid is the origin.** The saved sandbox records its name and its
ecoregion and *not* the centre it was built around, so there is no original
origin to read back. The centroid is also the better promise: the middle of what
you built lands on your pin.

**With no pin it still graduates**, at its own coordinates, with the existing
first-step prompt asking for an address. Refusing would put a wall exactly where
the feature is trying to open a door.

## What was deliberately left alone

- **The other five Group E rows.** F105 and F88 are real work of their own; F85,
  F107 and F83 are blocked on art, a conversation and photo content respectively.
- **`app_mode._LEARN_ONLY` itself.** Graduation is a sanctioned crossing of the
  mode split, not a loosening of it — it only ever runs from an explicit press.
- **Redo.** Undo answers the complaint; redo is a second stack and a second
  button on a bar that just gained two.

## How it was verified

Three new modules, 39 new tests, all Qt-free except where the point is the widget.

- **`test_glossary.py`** — the table, plus **two** wiring layers: a source scan
  pairing panel and glossary in both directions (runs anywhere), and a
  **real-widget test** that builds the panel offscreen and reads tooltips back
  off the actual caption widgets. The V2.37 dead-control bug is why a source scan
  alone is not trusted here.
- **`test_sandbox_undo.py`** — plant, pull and **reset** all reverse; restores in
  place; bounded; empty undo is a no-op; a corrupt entry is skipped rather than
  raised. Plus a source guard that each mutating handler snapshots *before* it
  mutates — snapshotting after would restore the state the user was escaping.
- **`test_graduation.py`** — the centroid is a mean and not a bbox centre;
  relative offsets and pairwise distances survive the move; the sandbox is left
  untouched; site data is carried and copied not aliased; the no-pin path
  produces a valid project.

Beyond the suite, the transform was measured directly: 32 plants moved Calgary →
Edmonton with **0.000000 m** worst-case offset drift. And the bar was driven end
to end with real Qt widgets — plant → Undo enabled, tooltip reading *"Undo
planting the Wild Rose."* → undo → plant gone, button disabled again; and a
four-plant landscape wiped by Reset and brought back by Undo.

Full suite: **2887 tests, OK, 98 skipped** — with `libegl1` and `PyQt6-WebEngine`
installed first, since without them ~200 widget tests skip silently.

## What could not be verified here

- **Nothing was rendered.** No display, and this container segfaults tearing down
  `QWebEngineView`, so the reference window itself was never opened. The bar was
  exercised against a stand-in window with real widgets; how it *looks* beside
  the roster, and whether "🎓 Take into Design" reads as clearly as intended, need
  a desktop.
- **The graduation has never been run against a real MainWindow.** Every piece
  is tested — transform, save, loader name, pin read — but the actual crossing
  needs the app up.
- **`tests/test_undo_redo.py`** still segfaults in-container, as documented; it
  never loads the surfaces this increment touched.
