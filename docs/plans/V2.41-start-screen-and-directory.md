# V2.41 — a start screen, and the plant directory behind it

## The ask

> *"I would like a start up page (modal if you will) to boot up as the first
> thing the user sees, before the map loads. This start/landing page will then
> direct the user to start a new design, load a previous design or explore the
> plant directory (which we have not built yet but I think would be an excellent
> feature of a native plant education app and we have all the data)."*

V2.40 answered half of this and did not know it. It moved the welcome ahead of
the map, which was the ordering question — but what it moved was still a 520px
dialog with three buttons, and it had no third door to send anyone to.

That last clause is the argument for the rest: **we have all the data.** The
catalogue holds 434 species with ~70 fields each, their documented animals,
their sourced ranges with occurrence counts, their twelve-month calendars — and
the only way to see any of it was to open a design and use the browser beside
the map. That browser is a *picker*. Its job is to get a plant onto the ground
and every affordance in it points that way. A reference work is a different job.

Branch: **V2.41**. Roadmap: **F90 · Plant directory**.
Principles: P5, P6, P10, P13.

## What shipped

### The start screen (`src/start_screen.py`)

```
  ⏱  Recover unsaved work            ← only after a crash
  ↩  Continue — "Back Yard Meadow"   ← only if it still exists
  ─────────────────────────────
  🌱  Start a new design
  📂  Load a design
  📖  Explore the plant directory
  ─────────────────────────────
  🌾 Open the worked example  ·  🌲 Walk a reference ecosystem

  🌼 41 species are in bloom this August in Aspen Parkland →      V2.41 · Check for updates
```

`welcome_dialog.py` is **deleted**. One start surface, not two — Help → Welcome
reopens this one, and both entry points build it from a single `_open_menu`
body so they cannot drift about which rows exist.

**Generate a design comes off the screen**, on the author's call: *"it needs a
lot of work before it is usable and I don't want to lead with generate design as
people will associate this with AI."* It was the primary button in V2.40. It
keeps `File → Generate Design…` and Ctrl+G, unchanged.

Two rows that already existed and were buried get one line each: the worked
example (behind Help) and F50's walkable reference ecosystem (behind View).
Neither is new work; both were unfindable.

### The plant directory (F90)

`PlantDirectoryWindow`, a top-level window opened from the start screen with **no
MainWindow in existence**, and from `View → Plant Directory…` once there is one.
The singleton pattern is `open_3d_view`/`open_snapshot_view`'s, with `main`
optional — being usable without a design is the point.

List on the left, species page on the right. What it did not have to build:

| | |
|---|---|
| The list | `PlantListModel` + `PlantRowDelegate`, borrowed whole — virtualized, lazily photo-loading |
| The facets | `filter_widgets.make_multi_combo`, built for reuse in V2.13 |
| The query | `db.plants.search_plants` |
| Relationships | `db.relationships.neighbourhood` — grouped, coloured, name-resolved, evidence-tagged |
| Safety / sourcing / morphology wording | imported from `scene_dossier`, so the 3D inspect card and this page cannot disagree about the same plant |
| The quiz | `field_study.generate_quiz` already accepted an arbitrary plant list |

**The find worth recording: `search_plants` takes thirty parameters and the
design-side browser wires fourteen.** The other sixteen have worked the whole
time with nothing to press — keystone, larval host, bird food, pollinator,
nitrogen fixer, specialist support, pet safety, child safety, spread habit,
price, commonness, province, moisture and three fauna-keyed lookups. They are
research questions, not placement ones, which is why the picker never grew
controls for them. Thirteen are now chips on the directory, and a test asserts
every one names a real parameter — a facet with a typo'd key is a filter that
silently does nothing, which is the exact shape of the two dead controls V2.37
had to fix.

### The two honest bits

**Range evidence travels with the range.** A species page says "Subalpine /
Montane (434 records, high confidence) · Boreal Mixedwood (5 records, low
confidence)". Those are different claims and a page that printed them
identically would be inventing certainty (P9). Where nothing has been derived it
falls back to the heuristic column and says "no occurrence data" rather than
passing it off as sourced.

**The in-bloom line says "across the catalogue" when it has no location.** The
start screen runs before any project is open; the only location it can honestly
claim is the ecoregion of the design you were last in. "41 species are in bloom"
reads as a local claim and would not be one.

## Decisions

- **All three doors, always.** V2.40 hid "Load a design" until you had one, on
  the rule that a door to an empty room is worse than no door. Right for a bonus
  row; wrong now that these three *are* the screen. A structure that rearranges
  itself between your first and second launch is harder to learn than one honest
  empty room — and the row's second line says "Nothing saved yet", while the
  saves browser it opens offers Browse… for a design kept elsewhere.
- **The window is built behind the screen.** On a zero-timer that fires inside
  the screen's own modal loop. Constructing `MainWindow` is a few hundred ms and
  starts no threads, but it kicks off the Leaflet load, which is asynchronous and
  is the part that actually costs seconds. Without it the screen would be a
  straight regression in perceived speed: the V2.40 dialog already had the map
  loading behind it. Nothing is *shown* until a door is picked.
- **Only rows that draw a project wait for `map_ready`.** Opening the directory
  or a reference ecosystem touches no map; making those sit through a Leaflet
  load would be a delay bought for nothing.
- **A widget tree for the species page, not the delegate's painted block.** The
  existing expand-in-place detail is drawn with QPainter — its text cannot be
  selected and its relationships cannot be clicked. Fine for a picker.

## Considered and rejected

- **"Add to my design" from a species page.** Your call, and it is the right
  one: it couples the directory to a window that may not exist.
- **Guided lessons in the directory.** `lesson_track.py` and `docent.py` read
  the user's placed plants. A catalogue-wide mode is real work and half of it
  would be worse than none. The learning hook that *is* free — Field Study over
  the current filter — shipped.
- **The drawn vocabulary.** 33 botanical + 37 zoological SVGs sit in `docs/img/`
  and a page saying "spoon-shaped leaves" ought to show the picture. Needs a
  PyInstaller `datas` entry and a term→asset map. Second cut.
- **Fauna pages.** `db.fauna.plants_for_fauna` is the reverse direction and
  would make the directory bidirectional. Own increment.

## Risks

| Risk | Guard |
|---|---|
| A facet drifts from `search_plants` | Test checks every key against the real signature |
| The directory grows into `plant_panel.py` | It is at **1600/1600**, zero headroom; a test asserts the directory does not touch it, and the ceiling comment now names the extraction the next edit owes |
| Photos are uneven | 323 of 434 species have one and the 7-slot table ships empty; the page says "No photograph of this species yet" rather than drawing an empty frame |
| P12 | A test scans labels and headings — not docstrings, which must be allowed to name what they forbid — for ethnobotanical vocabulary, and is itself checked against a file that violates it |

## Verification

- `QTWEBENGINE_CHROMIUM_FLAGS=--no-sandbox python -m unittest discover -s tests -t .`
  (`tests/test_undo_redo.py` segfaults at teardown in a container — see CLAUDE.md).
- Qt-free: facet→parameter mapping, sort fallbacks, range evidence, specialist
  counting, one failing source costing its section and not the page.
- Widget: opens with no MainWindow; every facet and toggle drawn; a toggle, the
  search box and a facet each *narrow the result*; the species page carries
  range evidence; no snake_case and no colour hex reaches the screen; `preset`
  replaces rather than merges; the quiz receives the filtered set.
- By hand: launch with nothing saved and confirm three doors and an honest Load
  row; open the directory from the start screen with no design open; filter to
  keystone and watch the count change; click a species with no photo.
