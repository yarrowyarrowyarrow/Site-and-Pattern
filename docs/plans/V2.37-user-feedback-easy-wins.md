# V2.37 — record the feedback, ship the easy wins

*Backfilled: this increment predates the plans directory, written up from the
session that produced it so the series starts where the habit started.*

## Context

The first person outside the project used the app and sent sixteen observations
across two messages. The ask was twofold: **record it all** so nothing is lost,
then **act on the easy wins**. Ten shipped here; the rest became Theme G in
[`ROADMAP_NEXT.md`](../ROADMAP_NEXT.md) (F85–F89).

The finding that shaped everything else: **most items were not missing
features.** They were working features with a dead control in front of them, a
legend buried on page 4 of a PDF that could not be produced, or a facet never
wired to data the app already parsed.

## What shipped

| # | Feedback | What it actually was |

| 1 | "Using the quiz in the Learn tab crashes the app!" | `new_quiz` returned early on failure while leaving the previous question's buttons live, so the next click indexed an empty list — and an `IndexError` escaping a Qt slot calls `qFatal()`, a process abort with no traceback. ## What this increment taught

- **Tests that skip are not tests.** PDF export was broken for four minor
  versions behind a green suite. The quiz widget had no tests at all. And
  `tests/test_pattern_placement.py` was running **zero** of its ~25 geometry
  cases — module-level functions `unittest` never collects — which was the
  canonical guard on the exact maths behind the row-placement bug.
- **A dead control is worse than a missing one.** The sun slider and the
  never-applied right/wrong colouring both taught users a feature existed and
  did not work.
- **Silent fallbacks hide missing data.** `moist_mixedgrass` reading
  "Generalist" was a lookup default doing exactly what it was told.
- **The suite needs `PyQt6` *and* `libegl1`.** Without both, ~156 tests skip
  silently. This is how the export bug hid.

## A correction worth keeping

The first diagnosis of the crash blamed `UnicodeDecodeError` on a torn read of
the photo index. Testing falsified it: `json.dump` defaults to
`ensure_ascii=True`, so the file is pure ASCII and truncation can only raise
`JSONDecodeError`, which *was* already caught. The lost-update race was real and
severe; the crash was the `IndexError`. Recorded because the wrong half sounded
just as plausible as the right one.

## Also fixed here, found while verifying

A **use-after-free** in the photo warmers: `plant_list_view` and
`analysis_panel` captured a *bound signal* and emitted from a worker thread, so
a fetch finishing after its widget was gone wrote into freed memory. Latent
before; the new widget tests started landing on it, and the full suite began
segfaulting in a module that does not touch Qt. `src/qt_safety.py` now checks
the object is alive before emitting.
