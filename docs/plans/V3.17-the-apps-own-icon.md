# V3.17 — The app's own icon (F232)

*The owner: "Can you update the icon of the app that appears on the desktop to be
this image? The worm on a file screams malware." Then two photographs to choose
between, a prairie crocus and a wild rose: "Lets compare the rose to the prarie
crocus". Numbered F232, the next free ID, and shipped with it.*

## What the "worm on a file" was

**PyInstaller's own icon:** a yellow Python snake on a blue floppy disk. The
build set no icon of its own: `permadesign.spec` had `icon=None` on both the
Windows `EXE` and the Mac `BUNDLE`. Left at `None`, PyInstaller uses the one in
its `bootloader/images` folder. I read it from the 6.22.3 wheel the release
builds install; it is the picture the owner described.

**Why it reads as malware.** A great deal of malware is packaged with PyInstaller
and never changes that icon, so people and antivirus tools have learned its
look. The rest of the app had nothing better:

- The installer wore NSIS's generic icon.
- The windows had no icon of their own, so Qt drew none.

## Choosing between two photographs

The owner offered both, and asked for them compared. Both were put through the
same treatment and drawn at the sizes Windows uses (48 px desktop shortcut,
32 px Start menu, 24 px taskbar, 16 px title bar) on a light and a dark desktop.

| | Prairie crocus | Wild rose |
|---|---|---|
| Photograph | 704 × 702 | 300 × 300 |
| At 48 px | Clear: one flower's outline against dark ground | Bolder: saturated pink fills the tile |
| At 16–24 px | Keeps its star shape, because the dark ground surrounds the bloom | A pink square with a dark centre: the petals touch every edge of the photo |
| Largest Mac sizes | Close to the source | Upscaled about 1.7× at 512 px: soft |
| Around Edmonton | On the list, documented (3 collections, nearest 31 km) | Prickly, Woods' and Prairie Rose are all on it |

**Both are local**, so that does not separate them. The rose is also Alberta's
provincial flower, much used in official branding, where the crocus is
distinctive. **The owner chose the crocus** ("Crocus is good"), and the
photograph is theirs ("The photo is mine"). That was asked because the icon
ships inside every install and the photograph is committed beside it. The rose
stays one regeneration away: change `SOURCE` and the two crops in
`make_app_icon.py`.

**Neither file carries metadata.** The crocus had none at all. The rose held only
an orientation tag and a stock Adobe ID, no author or location. The committed
photograph is guarded by a test, because a phone photo can carry the coordinates
of where it was taken (the rule `src/photo_import.py` applies to imported
photos).

## The change

**The files** are in `assets/icon/`, made by
`scripts/packaging/make_app_icon.py` from the photograph committed beside them:

- **Ten PNGs from 16 to 256 px**, the window icon.
- **`site_and_pattern.ico`** for Windows.
- **`site_and_pattern.icns`** for the Mac.

How they are made:

- **Two crops of the same photograph.** At 32 px and below only the bloom
  survives, so the small sizes are cut tighter than the large ones.
- **A rounded tile with a hairline edge**, so a pale flower still has an edge on
  a pale desktop. The small frames are lightly sharpened.

**The `.ico` is written by hand:** 32-bit bitmaps up to 128 px and PNG at 256 px.
That is how PyInstaller's own icon is made, read from its file. Two reasons not
to use Pillow's writer:

- **Its PNG-only output** is read by Windows since Vista, but not by every tool
  that handles an `.exe`'s icon.
- **Its bitmap option leaves out the 1-bit mask that each frame's header
  promises.** Its 16 px frame was 1,064 bytes where the format, and PyInstaller's
  own frame, are 1,128.

**The `.icns` is written by hand too:** nine PNG entries from 16 to 512 px.
Pillow's writer always adds a 1024 px entry, which here would only be an upscale.

**Where the icon now appears:**

- **`permadesign.spec`:** the `.ico` on the program (desktop shortcut, Start
  menu, taskbar, Settings → Apps) and the `.icns` on the Mac app. The PNGs are
  bundled at `assets/icon`.
- **`installer.nsi`:** the same icon on the installer and the uninstaller
  (`MUI_ICON`, `MUI_UNICON`). At the end of every install, update mode included,
  it tells the shell that icons changed (`SHChangeNotify`, `SHCNE_ASSOCCHANGED`).
  Windows caches icons by file and can go on drawing a replaced program's old
  icon on its shortcuts until the next sign-in.
- **`src/app_icon.py`, from `main.py`:** the icon on every window, the start
  screen included, at every size, so the title bar gets the hand-made 16 px
  frame rather than a shrunk 256. It also covers a source checkout, which has no
  `.exe` to carry an icon.

## Verified

- **`tests/test_app_icon.py`** (8 tests), reading the files with the standard
  library so nothing skips without Pillow:
  - Every PNG is present, RGBA, at its size.
  - The `.ico` holds the ten sizes as bitmaps with their masks, and PNG at 256.
  - The `.icns` holds the nine entries, each PNG at its size.
  - The photograph carries no EXIF or XMP.
  - The spec, the installer and `main.py` name these files.
  - Qt draws the window icon at every size.
- **NSIS 3.09, warnings as errors.** The installer's compile test now copies the
  icon into its stand-in tree.
  - The built installer contains the 256 px picture and the 16 px frame byte
    for byte.
  - A wrong icon path fails the compile, so CI guards it.
- **PyInstaller 6.22.3's own code:**
  - Its data collection expands `app_*.png` to exactly the ten PNGs, at
    `assets/icon`.
  - Its icon check passes the `.icns` unchanged.
  - Its Windows icon reader parses the ten frames, each frame's data matching
    its directory entry.
  - The spec itself was executed with stand-ins for PyInstaller's build steps,
    as Windows and as macOS: each platform names an icon file that exists.

**The suite** was run in this container as CI runs it
(`scripts/run_tests.py --exclude tests.test_undo_redo --max-skips 25`, with PyQt6,
WebEngine, rasterio, pyproj, shapely, numpy and NSIS installed):

- 4,754 tests: V3.16's 4,746 plus this release's 8.
- 0 failed and 0 errors, `RESULT: OK`.
- 11 skipped, every one an expected kind: Blender-only, root file permissions,
  a shallow clone.

## What could not be verified here

- **The icon on a real Windows desktop and a real Mac.** The release build on
  GitHub's Windows and macOS runners is the first time PyInstaller embeds it.
- **`SHChangeNotify` against Explorer's icon cache.** It is what installers that
  change an icon call, but it was not observed. If a desktop shortcut still
  shows the snake after the update, signing out and in clears it.
- **The frames Windows picks at 125–200% display scaling** (20, 40, 64, 96 px).
  They are provided, not seen.

## Left alone, on purpose

- **The website's favicon.** GrowNativePlants has its own name and was not asked
  about.
- **The "Unknown publisher" prompt.** That needs code signing (see F230's notes).
- **Taskbar grouping on a source checkout under Windows.** It runs as
  `python.exe`; the window icon now shows, but grouping by an AppUserModelID is
  separate.
