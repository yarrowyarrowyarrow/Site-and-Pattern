## Why FN-1 could not wait

The owner answered D1 with GPL-3.0. Every push to a V-branch publishes installers
that bundle PyQt6, which Riverbank licenses under the GPL v3, and the GPL does not
allow a program built on it to be distributed with a noncommercial restriction
added. A V3.18 installer under the PolyForm licence would be the conflict D1
names, published again. The change is a file, two paragraphs and a line in the
About box, so it came forward rather than holding the release back.

## Found on the way, and fixed

- **The PDF summary counted six types**, and wildflower, grass, sedge, rush,
  fern and aquatic were not among them: the example's 19 plants printed as
  *3 shrubs, 2 groundcovers*. Now every type (`pdf_export.type_breakdown`).
- **The PDF's notes page cut every line at the right edge** and dropped whatever
  ran past the bottom: the example's own notes printed *…carries from sprin*.
  They wrap, bullets hang, and long notes continue on a new page. Both found by
  rendering the example's PDF to images, which is how QF-1 was checked.
- **The updater read one page of releases.** With every push a prerelease, the
  last promoted release could sit more than 100 releases back, and the updater
  would then report that nothing was published. `list_releases` reads up to
  five pages.
- **The plan being replaced was handed to the generator as existing features**,
  so its pond would have kept the new plan out of the water. It is left out.
- **Two documents leaned on the old licence.** `DATA_SOURCES.md` justified
  redistributing CC BY-NC occurrence records partly by the app being
  noncommercial; it now says the data's licences travel with the data whatever
  the code's. The draft FNA permission letter told FNA the app is noncommercial;
  it now says GPL v3, with a note for the owner to reread it before sending,
  since FNA may weigh that differently.

## Decided, and why

- **Plan-failure wording by cause, not one sentence.** 09 §3.7 proposed *Couldn't
  make a plan. Check that your yard outline or bed is closed*, but the
  generator's real failures are *no plants matched your goals* and *no outline or
  pin*. Each gets its own plain sentence; the proposed one covers the rest. The
  generator's own words go to the log.
- **The milkweed's colour source is `checked`, not `flora`.** The evidence is two
  published descriptions read through a web search, not a flora read; the mark
  says so, and the correction names them.
- **GPL-3.0-only, not "or later".** The decision says GPL-3.0 and PyQt6 is v3.
  "Or later" is one line if the owner wants it.
- **The drift top-up only acts when a keep-out took members**, so a plan with
  nothing drawn is unchanged; members the boundary cuts off are still dropped,
  as before (that is PY-2 and PY-4's ground).

## The first push published nothing, and why

CI's tests passed on `12df81e`, and both installers built, but neither was
published: creating the `release-V3.18` release returned **403 *Resource not
accessible by integration***, although the job's token held `Contents: write`
(its setup log says so). V3.17's identical step had succeeded on 8 October.
The difference is the commit, not the step: **`12df81e` changed workflow
files**, and GitHub will not let a workflow's own token create a tag on a
commit that changes `.github/workflows/`, which needs a `workflows` permission
that token can never hold. `prerelease: true` was a red herring, since it
needs no more than any release.

**The rule from now on: a push to a V-branch must not end on a commit that
changes a workflow file.** The release is tagged on the push's last commit
(`target_commitish: github.sha`), so follow a workflow change with any other
commit in the same push. The commit after `f8016e8` (itself a workflow-comment
commit, pushed `[skip ci]`) is that commit, and carries no `[skip ci]` so the
installers are built and published from it.

## Could not verify here

- **The release workflows on GitHub.** They parse as YAML and the tests read
  them; the first real run is this push. That a later push to a promoted
  version makes it a prerelease again is the action's documented update
  behaviour, not observed.
- **The promote workflow** has never run; its `gh release edit
  --prerelease=false --latest` is the documented CLI. **Found after the push:**
  GitHub runs a hand-started workflow only from the default branch, so it
  cannot be run until the file is on `main`. Corrected in the docs; promoting
  on the release page needs nothing.
- **A real printer and a real desktop.** The PDF was checked as rendered images
  and by contrast arithmetic; the dialogs offscreen.
- **The milkweed's colour** rests on two web descriptions; a regional flora
  could still say otherwise (one 2019 identification sheet says pale pink).
