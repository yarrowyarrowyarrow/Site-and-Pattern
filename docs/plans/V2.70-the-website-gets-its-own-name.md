## The decision: two names, not a rename

`grownativeplants.ca` was registered mid-V2.69. The obvious reading of the ask
is "rename the project", and that is the wrong move. The app and the website
are different artefacts with different audiences:

- **Site & Pattern** is a design tool. Its name says what it does — you have a
  site, you apply a pattern. That reads to somebody who has already decided to
  design something.
- **GrowNativePlants** is a catalogue somebody lands on from a search engine.
  It says what the reader wanted before they had a word for it.

So `src/branding.py:APP_NAME` was left alone and a second constant was added
where the website's shell is built:

```python
SITE_NAME = "GrowNativePlants"     # src/static_site_render.py
```

One constant, in the module every page's `<title>`, header and footer already
pass through, so nothing had to be renamed twice. The desktop window titles,
the QSettings keys, the database path and the frozen `permadesign_api` symbols
are untouched — the same reasoning the V1.69 rebrand used for the internal
identifiers it deliberately kept.

**The app is named outright on the About page**, on the author's instruction,
rather than described anonymously as "the desktop application this catalogue
comes from". A reader who wants the tool should be able to find it.

## The CNAME, which is the part that would have broken silently

GitHub Pages stores a custom domain in a file called `CNAME` at the root of the
published branch. The publish flow replaces that branch's contents **wholesale**.
So a domain typed into the Pages settings survives exactly until the next
rebuild, and then the site reverts to `*.github.io` with the custom domain
404ing — no error, nothing in the build output, and the cause is a step nobody
performed.

`_custom_domain(base_url)` derives the host from `--base-url` and the build
emits the file. Derived rather than given its own flag, on the rule this
codebase keeps relearning: two settings that must agree, set separately, do not
stay in agreement. `--base-url https://grownativeplants.ca/` already says what
the domain is. A `*.github.io` base URL writes no CNAME, which is correct —
that would be GitHub redirecting to itself.

`.nojekyll` went in beside it for the same reason: it was in the published
branch because somebody had once added it by hand.

## What could not be checked from here

The sandbox proxy refuses CONNECT to both `github.io` and `grownativeplants.ca`,
and intercepts DNS — a query for a nameserver came back with a *web server's*
address, which produced one wrong diagnosis before it was caught. Everything
about the live domain was verified by the author from their own machine.
