## 1. The inference is withheld, not annotated

V2.78 put a mark on the nativity claim: *"Saskatchewan is inferred from
ecoregions that continue across the provincial border, not from a range map for
this species."* That was a real improvement on printing "AB, SK" bare, and it
was still an inference published as this site's answer to the question it is
named after.

After VASCAN, 414 of 430 claims are sourced and carry no mark at all. The
remaining **16** now show:

> **Not established.** No source we have read settles which provinces this
> species is native to, and this catalogue does not guess.

The province list is not printed for those species.

**The sentence is deliberately vague about why**, and that is the one judgement
call here. The 16 differ: VASCAN records *Achillea millefolium* as introduced
in both provinces, carries *Urtica dioica* only under a different accepted
taxon, and does not carry *Andropogon gerardii* at all. "Not established" is
true of every one of them. "No flora records it" would be false for most.

`nativity.publishable()` is a separate function from `provenance()` on purpose.
One asks *how sure are we*, the other asks *may we say it at all*, and
collapsing them would make the site's honesty depend on the wording of a note.

**Not done: the desktop app and the Habitat Value Score still use the
unsourced value.** `native_to_alberta` for those 16 drives the native filter
and the score, and blanking it would change what the app recommends. The
website is what the instruction was about; the app is a decision with a wider
blast radius and belongs in its own increment. Flagging it rather than doing it
quietly.

## 2. The range picture, with the toggle

### The two kinds are real, not a filter convenience

A herbarium specimen is a pressed sheet in a cabinet with a determination on
it, which somebody can go and re-examine. An iNaturalist observation is a
photograph identified by community agreement. Both are evidence; they are not
the same evidence, and a map that merges them silently asserts they are.

Specimens are **filled** dots, observations **hollow** rings — shape and not
only hue, so the split survives greyscale, print, and red-green colour
deficiency.

### The licence decision the author made in V2.79, implemented

`PUBLISHABLE = ("CC0", "CC_BY")` held coordinates to the bar a *photograph* is
held to. Measured over the 365,092 in-province, sufficiently precise records:

| licence | kind | records |
|---|---|---|
| CC_BY_NC | observation | **329,267** |
| CC0 | specimen | 23,568 |
| CC_BY | specimen | 6,255 |
| CC_BY | observation | 4,167 |
| CC_BY_NC | specimen | 1,835 |

The entire iNaturalist layer is `CC_BY_NC`. Publishing under the photograph
rule would have produced a map that is **94% herbarium specimens** and called
it the observation record — a distribution map of where the herbaria are.

`PUBLISHABLE_COORDINATES` adds `CC_BY_NC` for coordinates only, per the
author's V2.79 decision: *a photograph is redistributed as a work, a coordinate
is a fact about a place.* `PUBLISHABLE` is untouched, so the photograph
pipeline keeps the stricter rule, and a test asserts the coordinate set is a
strict superset — two independently maintained lists would eventually disagree
in the direction that leaks.

### One mark per 0.01 degrees, and why that is not subsampling

365,092 records become **171,896 marks**. 0.01 degrees is about 1.1 km and
**under half a pixel** at the size these maps are drawn, so two records 200 m
apart were already one dot.

That makes it a rendering decision. *Subsampling* would be an editorial one and
would need saying on the page. What a reader loses is the ability to count
dots, which was never a valid reading: dot density tracks collection effort.
The caption says so.

Median 219 marks per species; the widest is *Galium boreale* at 2,245.

### The ecoregion map is gone from the species page

Replaced, not supplemented. Three reasons, and the third decided it:

* **The shading was the overstatement.** A whole ecoregion coloured in because
  three records fall somewhere inside it claims 100,000 km² for them.
* **The dots are the answer to the question that was asked.**
* **It is smaller.** A species page was 888 KB, of which **846 KB** was 2,291
  ecoregion polygons repeated verbatim on all 430 pages. The built site was
  **421 MB**; it is now **118 MB**, and a species page **111 KB**.

That last point quietly closes F146, which the V2.79 handover had listed as
blocking this work. It was backwards: swapping the map *is* the fix.

**The ecoregion counts stay**, under a heading that now says what they are —
*Which ecoregions the records fall in*. A count is a fact. Only the picture
drawn from it overclaimed.

### The toggle is three radios and no JavaScript

`browse.js` is the site's only script and it is about the index pages. This
needs none: radios plus `:checked ~` sibling selectors, so the control works
with scripting off, saved to a file, and printed.

Two structural details are load-bearing, and the first cut got both wrong:

* **The inputs must be siblings of the map.** A general-sibling combinator
  cannot climb out of a wrapper. With the inputs nested inside `.ranketoggle`
  the buttons highlighted correctly and hid nothing — a control that looks like
  it works and does not.
* **The radio group is named per species.** Two maps in one document sharing
  `name="rk"` are one group, so checking either unchecks the other. That cannot
  happen on a species page today, which is exactly why it would have gone
  unnoticed until something rendered two.

Both are now tests. The layer-hiding CSS is also asserted against the markup,
because the rule and the element it targets live in different files and nothing
else checks they agree.

The `.only-spec` / `.only-obs` rules live **inside** the SVG, so a standalone
file toggles too; the stylesheet only drives them from the radios. With neither
class set both layers show, so a viewer with no CSS sees everything rather than
nothing.

## What the method page now discloses

Computed from the modules that own the numbers, never written down:

* what the shaded squares are (0.25°, ~28 km) and that **darker is more
  collecting, not more plant**;
* the two record kinds, and that of 171,896 marks, 24,726 are specimens;
* the three filters — 10 km precision, the two provinces, the licence — and
  **the NC judgement stated plainly** rather than left in a constant;
* that records closer than 0.01° are drawn once, and why that is invisible;
* a new section on nativity: 414 of 430 sourced, 16 withheld, and *"We would
  rather show you nothing than show you a guess."*

## The architecture guard fired, and it was right about something I had already broken

Three modules over their ceilings: `static_site_range` 291/260,
`static_site_method` 334/260, and `plant_directory` **607/600**.

That last one is the interesting one. `plant_directory.py` was at *exactly* 600
before this increment, and the nine-line comment I added in the previous commit
took it to 610 — which shipped, because the full-suite run I checked predated
that commit and the targeted runs after it did not include the guard. It was
red on `origin/V2.80` for one commit. The guard did its job; my test selection
did not.

All three were extracted rather than having their numbers raised, and each seam
was already named somewhere:

* **`src/static_site_points.py`** — the records and the toggle. `static_site_range`
  answers *which classified communities is this recorded from*; this answers
  *where exactly was it found*. They were one file only because the ecoregion
  map used to be the answer to both. It also took the `/method/` prose about the
  map, because the module that owns the data should own its disclosure.
* **`src/plant_directory_bloom.py`** — `in_bloom_now` / `bloom_line` /
  `catalogue_size`, the start-screen trio, which `plant_directory`'s own
  docstring already listed as a separate bullet. Re-exported so every caller
  keeps working, and `_safely` is imported inside the function to avoid the
  cycle that re-export creates.

## And the same mistake again, one commit later

The commit above was pushed on the strength of 207 green tests across every
module I had *touched*. The full suite then found three failures in
`tests/test_plot_occurrences.py`, which asserts the old licence rule:
*"a noncommercial dataset is not drawable."* It was right to, for three
releases, until this increment deliberately reversed it.

Two things this keeps proving. **A change to a shared constant reaches modules
you did not edit** — `PUBLISHABLE_COORDINATES` was a two-line edit in
`fetch_dataset_licences.py` and it changed what a dev-tool plotter draws.
And **"the modules I touched" is not the same set as "the modules affected"**,
which is exactly what a full suite is for and exactly what I substituted a
faster proxy for, twice in two commits.

The three are updated to the new rule rather than to make the failure go away,
and one is added that they did not cover: with the specimen filter in the way,
the unlisted-licence record never reaches the licence check, so *absent is not
permissive* needed its own test to still be guarded. A second new test asserts
`CC_BY_NC` is still **not** in `PUBLISHABLE`, so a future edit to the wrong
constant loosens the photograph pipeline loudly rather than quietly.

## Could not be verified here

- **How it looks on a real display.** Headless Chromium at 700–980 px is a good
  check and is not a monitor. The three toggle states were rendered and read
  correctly; a real browser's `:checked` behaviour was not exercised by a
  click, only by pre-setting the attribute.
- **The archive and the live databases.** `data.canadensys.net` and
  `api.gbif.org` both answer 403 at this environment's proxy. Everything here
  is derived from the cache the author fetched.
