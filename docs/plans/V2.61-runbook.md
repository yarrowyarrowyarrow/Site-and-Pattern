# V2.61 runbook — the two fetches, on your machine

Both need internet. The container answers 403 to CONNECT for `api.gbif.org`
and denies GloBI, so this half has to be yours. Nothing here writes to the
seed data; both scripts produce a file for review.

**Run the probes first.** Each takes seconds and is the difference between a
good run and hours of identical failures — which is not hypothetical, it is
what V2.59 did for 55 plants before anyone looked at the response body.

---

## 1 · Citations — the GloBI observation fetch (F128)

### ✅ Probed — and the answer decided the design

```bash
python3 scripts/fetch_fauna_edges.py --observations --probe
```

Run on 2026-08-16. Three hopes, three different answers:

| field | result | what it means |
|---|---|---|
| `study_title` | **100% populated** | **Go.** This is the whole ask, and it is there. |
| `target_specimen_life_stage` | **6%** | Thin. Of the 700 `larval_host` records refused for want of a stage, only a few dozen become resolvable. |
| body part | **absent, every spelling** | **Dead.** `/interaction` never returns it. Recovering the sapsucker and browse records this way is off the table, not deferred. |

**And note what `study_title` actually contains.** The first value sampled was
`https://scan-bugs.org/portal/collections/individual/index…` — a museum
specimen record, not a paper. Much of GloBI is collection aggregation, so
expect a large share of URLs. Those are still real citations: one identifiable
record a person can open, which is strictly more than "an aggregator has it".
The ingester files them as `kind: specimen_record` with the collection as the
title, and every record from one portal shares one bibliography key so the
file does not grow an entry per specimen.

So: **the run is worth making.** Go straight to it.

### The run

```bash
python3 scripts/fetch_fauna_edges.py --observations
```

- ~437 plants, several pages each. **Budget two to three hours**; observation
  mode returns one row per record rather than one per distinct interaction,
  so it is several times larger than the V2.59 run.
- Checkpointed after every plant. Ctrl-C and re-run resumes.
- Writes `data/fetched/fauna_edges_observations.json`. It does **not** touch
  `fauna_edges_candidates.json` — the V2.59 file stays exactly as it is.
- The summary ends with the three percentages again. If citations came back
  at 0%, it says so and tells you not to ingest.

## 2 · Nativity — the GBIF occurrence fetch

### ⚠️ Probed once, failed, and redesigned — probe again

The first probe (2026-08-16) gave:

```
Danaus plexippus     AB=370     SK=596     review  unstated  (no facet)
Callipepla gambelii  AB=0       SK=0       reject  unstated  (no facet)
Sturnus vulgaris     AB=267995  SK=15778   review  unstated  (no facet)
```

The occurrence counts are **excellent** — a monarch is here, a Sonoran desert
quail is not, and the numbers are unambiguous. Presence is solved.

**The starling failed exactly as feared.** No `establishmentMeans` facet came
back on *any* species, including a bird with 267,995 Alberta records that
every Albertan knows is introduced. GBIF occurrence records do not carry the
field in practice, so faceting them can never separate introduced from native.

**So the source changed.** Occurrence tells us *present*; checklists tell us
*introduced*. `/species/match` → `/species/{key}/distributions` returns
per-country rows contributed by checklist datasets, including **GRIIS** — the
Global Register of Introduced and Invasive Species, which is the register
built for this exact question. Two extra requests, made **only** for species
that already have AB or SK records, since one with none is rejected on the
count alone.

Probe again with the new path:

```bash
python3 scripts/fetch_fauna_nativity.py --probe
```

Now four species, and the output has a separate `checklists:` line:

| species | what it must say |
|---|---|
| *Danaus plexippus* | present in AB |
| *Callipepla gambelii* | absent |
| *Sturnus vulgaris* | **`checklists:` non-empty, verdict `reject`** |
| *Apis mellifera* | **same** |

The `occurrence facet:` line is expected to stay empty — that is the known
dead end, kept only so a future GBIF change is visible. **The `checklists:`
line is the one that has to work.** If both the starling and the honeybee come
back with an empty checklist line, GBIF cannot tell us what is introduced from
either direction, and the gate needs a source outside GBIF. Say so before
starting the full run.

### The run

```bash
python3 scripts/fetch_fauna_nativity.py
```

- 3,065 animals — the catalogue's 167 plus the 2,898 held. Two requests each
  for the occurrence counts, plus two more for the checklist lookup **only
  where there are AB/SK records to justify it**. **Budget three to four
  hours** at the polite 1/second pace.
- Checkpointed every 25 species; safe to Ctrl-C and re-run.
- A species GBIF *fails* on is **left out of the file entirely**, not recorded
  as absent, and the summary counts them. Re-run to pick them up.
- Writes `data/fetched/fauna_nativity.json`.

`--held` does only the 2,898 if you want the shorter run first;
`--limit 50` does a slice.

## What happens next, back in the repo

Nothing is merged automatically — same discipline as V2.59.

```bash
python3 scripts/ingest_fauna_edges.py --citations   # report
python3 scripts/ingest_fauna_edges.py               # report, now with the gate
```

The first upgrades `globi` edges to named studies, registering each distinct
study as a real record in `data/sources_master.json`. The second re-runs every
gate with the nativity data in place, and now refuses any new animal that has
no AB/SK records, too few of them, or a GBIF `establishmentMeans` saying
introduced.

Both print a full report and write nothing until `--apply`.

## Two things to know before you read the results

**Occurrence is not nativity.** A record count says an animal was *seen* here,
not that it belongs here — the starling probe is the proof, at 267,995 Alberta
records for a bird nobody would call native. Presence comes from occurrence
counts and origin comes from checklists, and where the checklists say nothing
the answer is `review / unstated`: present, origin unrecorded. Expect a lot of
those. It is an honest answer rather than a failed run, and the gate treats it
as "needs a human" instead of quietly deciding either way.

**Alberta's box overshoots.** Both provinces are surveyed rectangles, which is
why a bounding box works at all — but Alberta's western border follows the
continental divide south of 54°N rather than the 120°W meridian. The box
includes a sliver of British Columbia, up to ~1.5° of longitude wide at the
southern end. Records in it are Rocky Mountain records within kilometres of
the border, so it inflates Alberta counts for montane species and is accepted
rather than corrected.
