# V2.61 runbook — the two fetches, on your machine

Both need internet. The container answers 403 to CONNECT for `api.gbif.org`
and denies GloBI, so this half has to be yours. Nothing here writes to the
seed data; both scripts produce a file for review.

**Run the probes first.** Each takes seconds and is the difference between a
good run and hours of identical failures — which is not hypothetical, it is
what V2.59 did for 55 plants before anyone looked at the response body.

---

## 1 · Citations — the GloBI observation fetch (F128)

### Probe

```bash
python3 scripts/fetch_fauna_edges.py --observations --probe
```

It prints, for each of `citation`, `life_stage` and `body_part`, **every
spelling the code knows and what percentage of rows actually populates it.**

**Read that before going further.** The one number that decides whether the
run is worth making is the citation percentage. If every spelling reports 0%,
stop and send me the output — the run would produce nothing and take two
hours. This is exactly how V2.59 went wrong: `study_title` looked available
because the column *existed*, and 14,111 edges arrived with it empty.

### The run

```bash
python3 scripts/fetch_fauna_edges.py --observations
```

- ~437 plants, several pages each. **Budget two to three hours**; observation
  mode returns one row per record rather than one per distinct interaction,
  so it is several times larger than the V2.59 run.
- Checkpointed after every plant. Ctrl-C and re-run resumes.
- Writes `data/fetched/fauna_edges_observations.json`. It does **not** touch
  `fauna_edges_candidates.json` — the V2.59 file stays exactly as it is.
- The summary ends with the three percentages again. If citations came back
  at 0%, it says so and tells you not to ingest.

## 2 · Nativity — the GBIF occurrence fetch

### Probe

```bash
python3 scripts/fetch_fauna_nativity.py --probe
```

Three species, chosen to fail loudly if the query shape is wrong:

| species | what it must say |
|---|---|
| *Danaus plexippus* | present in AB |
| *Callipepla gambelii* | absent — a Sonoran desert quail |
| *Sturnus vulgaris* | present **and `reject / introduced`** |

**The starling is the real test.** If it comes back `review / unstated`
instead of `reject / introduced`, GBIF is not populating `establishmentMeans`
for these taxa, and the gate cannot tell an introduced species from a native
one on occurrence alone. Say so before starting the full run — that changes
the design, not just the data.

### The run

```bash
python3 scripts/fetch_fauna_nativity.py
```

- 3,065 animals — the catalogue's 167 plus the 2,898 held — at 2 requests
  each. **Budget about two hours** at the polite 1/second pace.
- Checkpointed every 25 species; safe to Ctrl-C and re-run.
- A species GBIF *fails* on is **left out of the file entirely**, not recorded
  as absent, and the summary counts them. Re-run to pick them up.
- Writes `data/fetched/fauna_nativity.json`.

`--held` does only the 2,898 if you want the shorter run first;
`--limit 50` does a slice.

## What happens next, back in the repo

Nothing is merged automatically — same discipline as V2.59.

```bash
python3 scripts/ingest_fauna_edges.py --citations   # report
python3 scripts/ingest_fauna_edges.py               # report, now with the gate
```

The first upgrades `globi` edges to named studies, registering each distinct
study as a real record in `data/sources_master.json`. The second re-runs every
gate with the nativity data in place, and now refuses any new animal that has
no AB/SK records, too few of them, or a GBIF `establishmentMeans` saying
introduced.

Both print a full report and write nothing until `--apply`.

## Two things to know before you read the results

**Occurrence is not nativity.** A record count says an animal was *seen* here,
not that it belongs here. GBIF's `establishmentMeans` is the only field that
distinguishes them and it is empty far more often than not, so most species
will come back `review / unstated` — present, origin unrecorded. That is an
honest answer, not a failure of the run, and the gate treats it as "needs a
human" rather than quietly deciding either way.

**Alberta's box overshoots.** Both provinces are surveyed rectangles, which is
why a bounding box works at all — but Alberta's western border follows the
continental divide south of 54°N rather than the 120°W meridian. The box
includes a sliver of British Columbia, up to ~1.5° of longitude wide at the
southern end. Records in it are Rocky Mountain records within kilometres of
the border, so it inflates Alberta counts for montane species and is accepted
rather than corrected.
